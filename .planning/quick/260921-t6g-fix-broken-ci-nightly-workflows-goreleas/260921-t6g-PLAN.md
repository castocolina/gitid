# Quick: unbreak CI/Nightly/Release — repin goreleaser to a version the pinned Go toolchain can build

CI has been red since 2026-09-05 and Nightly fails on every scheduled run. Root cause
(confirmed live by the requester via `gh run list` / `gh run view --log-failed`, and
re-confirmed locally during planning): `go install github.com/goreleaser/goreleaser/v2@v2.18.0`
cannot run under the Go toolchain this repo pins, so every workflow that calls
`make setup-env` or `make setup-env-release` dies at the bootstrap step.

## DECISION REQUIRED BEFORE EXECUTION — the target version is v2.17.0, not v2.17.1

The task brief specified `v2.17.1`. **That version does not fix the build.** The brief's
analysis accounted for the workflows' `go-version: "1.26.x"` pin (which the runner resolves
to go1.26.8) but not for `Makefile:112`:

```make
export GOTOOLCHAIN := go1.26.4
```

That export overrides the runner's toolchain for **every** make recipe, including
`setup-env`/`setup-env-release`. It is deliberate — the comment above it records that
"Go 1.27's standard library is newer than this pinned linter supports" (golangci-lint
v2.12.2). It is also exactly why the CI error text reads `running go 1.26.4` even though
the runner's own `GOVERSION` dump says `go1.26.8`.

Evidence gathered during planning (real commands, real output, this machine):

| Probe | Result |
|-------|--------|
| `GOTOOLCHAIN=go1.26.4 go install github.com/goreleaser/goreleaser/v2@v2.18.0` | `requires go >= 1.27.0 (running go 1.26.4; GOTOOLCHAIN=go1.26.4)` — exit 1 (reproduces CI locally) |
| `GOTOOLCHAIN=go1.26.4 go install github.com/goreleaser/goreleaser/v2@v2.17.1` | `requires go >= 1.26.5 (running go 1.26.4; GOTOOLCHAIN=go1.26.4)` — exit 1 (**the brief's fix still fails**) |
| `GOTOOLCHAIN=go1.26.4 go install github.com/goreleaser/goreleaser/v2@v2.17.0` | exit 0; binary reports `GitVersion: v2.17.0`, `GoVersion: go1.26.4` |

Upstream `go` directives, read live from `proxy.golang.org/github.com/goreleaser/goreleaser/v2/@v/<ver>.mod`
on 2026-09-21 (this is the "fresh verification" the existing pin comment demands):

| goreleaser | requires |
|------------|----------|
| v2.18.2 / v2.18.1 | go 1.27.1 |
| v2.18.0 | go 1.27.0 |
| v2.17.1 | go 1.26.5 |
| **v2.17.0** | **go 1.26.4** |
| v2.16.0 | go 1.26.3 |

**Option A (this plan's default): pin `v2.17.0`.** Newest goreleaser buildable by the
existing `GOTOOLCHAIN := go1.26.4`. One line + its comment change. Honors every stated
constraint literally: no workflow `go-version` edit, no `go.mod` edit, no GOTOOLCHAIN edit.

**Option B (documented alternative, NOT executed without a new instruction): pin `v2.17.1`
AND bump `GOTOOLCHAIN := go1.26.8`.** Still 1.26.x, still golangci-lint-v2.12.2-safe (same
minor), and it aligns make's toolchain with what `actions/setup-go` already installs for
`1.26.x` — removing a redundant go1.26.4 download in every CI job. Larger blast radius:
GOTOOLCHAIN feeds `GOFMT`'s GOROOT lookup and `GO_BOOTSTRAP_VERSION`'s tarball fallback,
so `make fmt`/`make lint`/`make test` all need re-running. If the user prefers B, Task 1 is
the same work with two variable values changed and the same verification battery.

If execution starts without a redirect, implement **Option A**.
