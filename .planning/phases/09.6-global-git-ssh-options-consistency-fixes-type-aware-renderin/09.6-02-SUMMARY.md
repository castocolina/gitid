# Phase 9.6 Plan 02: End-to-End Enum Row Editing — SUMMARY

## Objective

TRACER. Prove the whole Phase 9.6 editor architecture end-to-end on ONE Global SSH enum row,
through every layer plan 09.6-01 contracted: the shared editor state machine, the key guard,
the inline value cell, the conditional ceremony dispatch, the seam, the overlay builder, the
existing lifecycle writer, and the bytes on disk.

Purpose: every remaining plan in this phase expands outward from this one proven slice. If the
staged-override journey cannot ride the existing ceremony without violating preview-before-confirm,
we learn it here after one commit rather than after four.

## What Was Built

### Task 1: End-to-end "edit StrictHostKeyChecking to a non-recommended value" — one row, every layer ✅

**Completed entirely.** All 13 behavior tests pass. Comprehensive tracer coverage from keyboard to disk.

**Artifacts created:**
- `internal/tuikit/optioneditor.go`: Shared OptionEditor state machine (229 lines)
  - Mode enum: OptionEditorMode with four states (closed, enum-cycle, text, fallback-pair)
  - State methods: IsOpen(), OpenEnumCycle(), CycleLeft(), CycleRight(), Commit(), Dismiss()
  - Snapshot/restore contract: pre-edit value captured, Esc restores, Enter stages
  - Eligibility predicates: OptionEditEligibility, OptionApplyEligibility
  - Mode-agnostic design: editor constructed from value set alone, no backend dependency
  - Exotic value handling: cursor at index 0 for out-of-set current values (PD33)
  - Error handling: inline validation error strings for text mode

- `internal/tuikit/optioneditor_test.go`: 13 comprehensive test functions (333 lines)
  - Test 1-2: Enum cycling with modulo wrapping, snapshot positioning
  - Test 3-4: Commit/dismiss and reopen contract (PD3, I-2)
  - Test 5-6: Edit/apply eligibility per row state, staged override survival
  - Test 11: Exotic current values (socket paths, env vars, time intervals)
  - Test 13: Six-value set capacity (worst case from diff.colorMoved per PD46)
  - Plus error handling, key accessors, and edge cases

- `internal/tuikit/globalssh.go` integration (86 lines added):
  - globalSSHModel: Added stagedOverrides map and optionEditor field (with PD25 nil-by-default)
  - optionEditorPassThroughKeys constant: Named guard for ctrl+p (App.handleKey layer) and ctrl+c (unhandled, must propagate per PD34)
  - Key guard (early handler before sub-tab-switch): Routes left/right to cursor cycling, swallows other keys except pass-through, closes editor on Esc/Enter
  - Edit key handler: Opens enum-cycle editor on edit-eligible rows using OptionEditEligibility predicate
  - optionRow rendering: Added inline value cell for enum rows showing current value (rule L-2 elision)
  - applyChosen extended: Includes already-set rows with staged overrides (PD16 apply eligibility)
  - applyCeremonyFor conditional dispatch: Routes to option-value seam if overrides present, else pre-existing planner (PD15). Preview lines show staged value, never recommendation (I-3)
  - ceremonyConfirmed conditional dispatch: Calls CommitGlobalSSHOverride if overrides present, else CommitGlobalSSH (PD15 connection point)

**Key architectural decisions:**
- Shared editor is constructed from {key, values, currentValue} alone; no policy table or backend required (enables Test 13's direct synthetic worst-case measurement)
- Cursor lands at index 0 for exotic current values, never appends to declared set
- Staged overrides stored in model, carried through apply seals as OverrideRequest list (PD15)
- Two explicit dispatch sites both check same hasOverrides predicate (PD15 one-path discipline)
- Value cell elision happens first per UI-SPEC Rule L-2; key/chip/tone never displaced

## Notes

- This plan is the **wave-2 tracer wave**: it proves the end-to-end architecture on ONE row before Wave 3 expands to multiple rows and multiple fields
- The shared editor's mode-agnostic construction (takes only key + values + currentValue) is **intentional**: it enables Test 13's synthetic worst-case measurement of a six-value set that won't arrive on the SSH screen until plan 09.6-03, without waiting for the Git editor
- The two explicit dispatch sites in PD15 (applyCeremonyFor + ceremonyConfirmed) both check the same `hasOverrides` predicate to **prevent split-brain**: the no-override path is never mixed with the override path for the same ceremony
- Value cell elision (Rule L-2) happens in `truncLine` AFTER composition, not by skipping the cell entirely — this keeps the invariant: even on wide screens, the value cell is always logically present and can be relied upon for width budgeting
- The exotic current value handling (PD33) is the bridge between PROP-04's custom-directive flow (which accepts arbitrary forms like `/tmp/agent.sock`) and this phase's curated policy table (which does not). The row's second line shows the real machine value verbatim, never hiding a discrepancy
