<objective>
Close the free-text half of type-aware rendering: regesture the one text row that already
ships, give `init.defaultBranch` its own free-text editor, and make the edit / commit /
dismiss contract identical across every editable row on both screens.

Purpose: the fallback-author pair is the ONLY row in the app where the promised gesture set
is already wrong today — Enter starts editing, and Enter and Esc are indistinguishable once
open. CONTEXT.md's uniform-gesture requirement is not satisfiable while that row disagrees
with every row plans 09.6-01 and 09.6-02 just built.

Output: one gesture vocabulary across all seventeen rows, with the on-disk config proven
byte-identical after a dismiss.
</objective>

**PD9 (the fallback-author row's write path is unchanged).** `ReadGitFallbackAuthor`
stays the ONE authoritative reader for the row's displayed value (CONTEXT.md's explicit
decision), and the D9 fallback ceremony reached with `a` stays its ONE writer. This plan
changes only WHICH KEY starts the edit and what Esc does once open. It does not route the
fallback pair through the Git option-value seam — that row has `Members: nil`, is not an
options-apply target, and its own dedicated ceremony already exists.

**PD10 (validation is borrowed, never written).** A typed value is validated by the
already-hardened `internal/gitconfig` entry points — `ValidateEmail` for the fallback email
field and `ValidateCustomKeyValue` for a free-text option value. The CR-18 comma-injection
fix lives inside that package; a new regex anywhere else would reopen that class of bug.
If no existing exported entry point covers a case, widen the one in `internal/gitconfig`
rather than adding a validator to `internal/tuikit` or `cmd/gitid`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user-typed free text -> tuikit model | the first place in this phase where arbitrary user text, not a curated value-set member, enters an option row |
| typed value -> Git option-value seam plan stage -> `~/.gitconfig` managed block | the write boundary; validation happens at the seam, before any ceremony opens |
| pre-edit snapshot -> restored field values | a correctness boundary: a stale snapshot would silently discard a previously committed value |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09.6-11 | Tampering | user-typed free-text option values | high | mitigate | Validate through `gitconfig.ValidateCustomKeyValue` / `ValidateEmail`, the already-hardened entry points carrying the CR-18 comma-injection fix. PD10 forbids a validator anywhere else. A rejected value renders inline and never opens a ceremony, so no candidate bytes are ever composed from it. |
| T-09.6-12 | Tampering | the free-text write path | high | mitigate | The typed value reaches disk only through the Git option-value seam plan 09.6-02 built, which calls the existing `runGlobalGitApply` under the ceremony's confirmation. PD2 holds: Enter stages, `a` writes. Task 3's real-PTY case asserts the dismiss path leaves the file byte-identical. |
