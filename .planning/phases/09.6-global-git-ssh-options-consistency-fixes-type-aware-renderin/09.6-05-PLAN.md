**PD38 (the author pair's resolution rule and its six-case display contract).** Cycle-2 review
found the plan asserting only that the fallback keys are ABSENT from the general list, while
`globalgit.AllSetKeys` (`internal/globalgit/properties.go:5-22`, `:46-56`) returns the
effective last-wins entry plus an origin and cannot by itself distinguish a managed block from
an external value in the SAME file. Both halves are now defined.

*The resolution rule (three named projections, not one blurred value).*
- **Managed pair** = whatever `gitconfig.ReadGitFallbackAuthor` parses out of gitid's own
  managed block. This is the ONLY projection that reflects what gitid wrote.
- **Effective pair + origin** = the winning entry `globalgit.AllSetKeys` reports for each of
  the two raw keys, run through the SAME non-repository probe constructor the Options probe
  already uses (RESEARCH Pitfall 1 — any other working directory folds a repository's local
  scope into a screen labelled Global). "Winning" means what `git config --get` would return,
  which is git's own last-wins resolution — the plan does not re-implement precedence.
- **SuppliedByManaged** = true when the managed pair is non-empty AND the effective value
  equals it AND the winning origin is the gitid-managed file. It is FALSE — and the origin is
  named — whenever a later entry wins, INCLUDING when that later entry lives in the same file
  outside gitid's block, which is precisely the case a file-identity comparison would get
  wrong. Determining managed-ness from the BLOCK (via `ReadGitFallbackAuthor`) rather than
  from the FILE is what makes the same-file case correct.
- Cases the resolution must cover and pin by test: managed block only; same file, outside the
  block; a different file at the same scope; system scope beating or losing to global;
  a multi-valued key set twice in one file; and the key absent everywhere.

*The display contract (six combinations, one row per test).* The Options fallback row is the
ONE home for both keys (PD21), so its rendering is stated exhaustively rather than left to the
three `fallbackCurrentLabel` branches alone:

| # | Managed | Effective | Row cell shows | Detail pane says |
|---|---------|-----------|----------------|------------------|
| 1 | both set | equals managed | the managed pair | gitid-managed; no second origin line (PD22-style: no redundant note) |
| 2 | empty | both set | the effective pair | the effective values and their origin file(s), named |
| 3 | both set | differs (later entry wins) | the EFFECTIVE pair | the effective values with their origin, AND that gitid's managed block holds a different pair that is being overridden |
| 4 | name only | name managed, email external | the composed pair | per-field: which half is gitid-managed and which half's origin file supplies the other |
| 5 | email only | email managed, name absent | the single field via the existing `fallbackCurrentLabel` branch | which half is managed; the missing half reads as unset, never as blank-because-error |
| 6 | empty | empty | the existing unset sentinel | nothing is set anywhere — distinct from a probe error |

A probe ERROR is a seventh, separate state and must render the unset sentinel plus its own
error treatment, never a half-populated pair (already Task 1 behavior Test 5's contract in
plan 09.6-04). (Resolves the cycle-2 09.6-05 MEDIUM "the raw partition proof must include the
effective-author representation as a formal third projection" and the 09.6-04 MEDIUM "no
defined display contract for partial or external-origin fallback pairs".)
