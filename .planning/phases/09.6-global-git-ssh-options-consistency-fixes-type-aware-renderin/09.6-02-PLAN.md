**PD7 (Git value-domain classification, verified this session).** Verified against
`git version 2.55.0`'s own `git help config` / `git help diff` on the planning machine,
not recalled from training data:

| Policy row (display key) | Kind | Value set |
|---|---|---|
| `init.defaultBranch` | text | any valid git ref name — see PD8 |
| `core.ignorecase` | bool | — |
| `core.autocrlf / core.eol` | bundle | — (two members applied as one unit) |
| `user.email (global fallback)` | text | — (owns the D9 fallback-author writer; plan 09.6-03) |
| `user.useConfigOnly` | bool | — |
| `push.autoSetupRemote` | bool | — |
| `pull.rebase` | bool | — |
| `fetch.prune` | bool | — |
| `alias (8 shortcuts)` | bundle | — (eight members applied as one unit) |
| `color (ui/branch/diff/status)` | bundle | — (four members applied as one unit) |
| `merge.conflictstyle` | enum | `merge`, `diff3`, `zdiff3` |
| `diff.colorMoved` | enum | `no`, `default`, `plain`, `blocks`, `zebra`, `dimmed-zebra` |

`diff.colorMoved`'s deprecated `dimmed_zebra` underscore synonym is deliberately not
offered. Bundle rows are the third structural category CONTEXT.md's three-way taxonomy
never named: they are apply-or-not gates over a whole preset, so they keep today's
checkbox-only rendering unchanged, which is what CONTEXT.md's "unchanged from today"
clause already promises for the apply-or-not case.

**PD8 (RESEARCH Open Question 1 — `init.defaultBranch` is text, and nothing breaks).**
Its real value domain is any valid git ref name, so the honest classification is text.
RESEARCH.md's Pitfall 5 warned this would break roughly ten existing assertions — that
warning assumed the subtractive reading of CONTEXT.md in which a text row loses its
checkbox. Under PD1 the checkbox stays on every row, so `init.defaultBranch` remains
selectable, `space`-toggleable and `chosen`-map-driven exactly as its ~41 existing
assertions in `internal/tuikit/globalgit_test.go` pin it, and simply gains an inline value
plus (in plan 09.6-03) a free-text editor. The executor MUST confirm this empirically:
run the existing Global Git suite unchanged before touching any test file, and if any
assertion does break, fix the RENDER, not the assertion, unless the assertion is provably
about a behavior CONTEXT.md changed.
