**PD29 (a state is registered on the surfaces it can actually be driven on, and the capture
functions decide that, not the registry).** Both capture functions require a frame for every
spec applicable on EITHER surface, so "applicable on the dummy only" is not expressible today
without a frame from the real capture too. Therefore each new state takes exactly one of two
routes, chosen per state and recorded in the SUMMARY:
- **Route A (preferred):** make the state reachable on BOTH surfaces — seed the gate's fixture
  HOME so the real backend produces it and add the mirroring fixture row so the dummy does —
  then drive it with explicit keystrokes in both capture functions.
- **Route B (fallback):** record it non-applicable on both surfaces with a `NonApplicability`
  entry naming the real-PTY case that carries its evidence instead, following the convention
  the existing differs/probe-error records already use.

Route B is legitimate only when Route A would require a second, incompatible fixture HOME for
one capture run. Choosing Route B for convenience is what produces a requirement marked
complete with no comparable evidence — the failure mode this plan's threat register calls out.

**PD41 (Route-B evidence is MACHINE-linked to a real test, not named in prose).** Cycle-2
review verified that `ValidateScreenSpecs` (`internal/screenshot/createflow.go:744`, checks at
`:765-780`) only asserts a non-applicability record has a non-empty `Decision`, a valid
decision-ref prefix, a non-empty `Reason` and a valid `Classification`. It never verifies that
a named real-PTY case exists, still exists, or produced anything. Under the previous wording a
plan could mark a state non-applicable citing a plausible-sounding test name that was never
written, and the visual gate would pass. Four changes close that:

1. **A machine-readable field.** `SurfaceNonApplicability` gains `EvidenceTest string` — the
   exact Go test function name carrying the state's alternative evidence. Prose in `Reason`
   stays, but it is no longer the only link.
2. **A required field for this phase's records.** `validDecisionRef` gains this phase's
   `UXG-D-` prefix (following the `GSSH-D-`/`GGIT-D-` precedent the file already documents),
   and `ValidateScreenSpecs` requires: for any non-applicability record whose `Decision`
   carries that prefix, `EvidenceTest` MUST be non-empty and MUST match a Go test-identifier
   shape. Existing records from earlier phases are untouched and keep validating exactly as
   they do today — this is additive, not a retro-fit of thirty pre-existing entries.
3. **Existence, resolved by a source walk.** A new test walks `e2e/` and collects every
   `func TestXxx(t *testing.T)` declaration, then asserts EVERY non-empty `EvidenceTest` in
   the whole registry resolves to one — failing by screen ID and test name when it does not.
   This is the same source-walk technique plan 09.6-05's PD28 uses for retired literals, and
   it is written RED first against a deliberately bogus name before the real ones are added.
4. **It actually runs.** The plan's own verify step executes the named cases through the e2e
   build tag with an anchored `-run` pattern and fails when the run reports no tests matched
   — so "exists" and "passes" are both proven, which is what the reviewer asked for.

(Resolves the cycle-2 09.6-06 HIGH and cross-plan HIGH "Route-B visual evidence is not
machine-linked to real-PTY tests or frames".)

**PD42 (the fail path is a persistent automated negative control, not a one-off manual
perturbation).** "Perturb the render, observe a failure, revert" is an execution-time ritual
that leaves nothing behind: the next commit has no proof any entry can still fail. Replace it
with a real test. For every ScreenSpec this phase adds, a negative-control test takes the
captured frame, perturbs the extracted text of each `RequiredRegion` in memory, and asserts the
comparison reports inequality NAMING that screen and that region — then asserts the unperturbed
frame compares equal. No source is edited and nothing is reverted, so it runs on every future
commit rather than once. The one-time manual perturbation stays as an additional confidence
check the executor records in the SUMMARY, but it is no longer the contract. (Resolves the
cycle-2 09.6-06 MEDIUM "'fail path observed and reverted' is a manual instruction, not an
automated regression contract".)
