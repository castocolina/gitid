driver and fixture as one unit.

<authority>
This plan inherits every decision the five preceding plans lock in their `<authority>` blocks.
It introduces no new product behavior. The one it is the first to EXERCISE is PD23 (visual
evidence lands as ONE atomic change per state).

**PD29 (a state is registered on the surfaces it can actually be driven on, and the capture
functions decide that, not the registry).** Both capture functions require a frame for every
spec applicable on EITHER surface, so "applicable on the dummy only" is not expressible today
without a frame from the real capture too. Therefore each new state takes exactly one of two
routes, chosen per state and recorded in the SUMMARY:
- **Route A (preferred):** make the state reachable on BOTH surfaces — seed the gate's fixture
  HOME so the real backend produces it and add the mirroring fixture row so the dummy does —
  then drive it with explicit keystrokes in both capture functions.
- **Route B (fallback):** record it non-applicable on both surfaces with a `NonApplicability`
  entry naming the real-PTY case that carries its evidence instead, following the convention
  the existing differs/probe-error records already use.

Route B is legitimate only when Route A would require a second, incompatible fixture HOME for
one capture run. Choosing Route B for convenience is what produces a requirement marked
complete with no comparable evidence — the failure mode this plan's threat register calls out.
</authority>

warning glyph; the Options fallback row showing its authoritative author pair; and the renamed
general-keys sub-tab in browse mode. Register each on BOTH Options screens where both screens

a navigation sequence plus the edit key plus a cycle key. For the differs state, Route A means
seeding the gate's fixture HOME with one conflicting config value so the real backend classifies
that row as differs, and adding the mirroring fixture row so the dummy does too; note in the
SUMMARY that this changes the baseline browse frames as well, which is expected and is why Task
