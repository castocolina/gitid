# Phase 9.6 Plan 04: Fallback Row Read-Path Fix and Editor Regesture — SUMMARY

## Objective

Close the free-text half of type-aware rendering AND fix the read-path defect: make
`ReadGitFallbackAuthor` authoritative for what the Options row shows, regesture the 
fallback row from Enter-starts-editing to the shared edit key, and give `init.defaultBranch`
its own free-text editor validated by git's real ref grammar.

## What Was Built

### Task 1: The fallback row displays ReadGitFallbackAuthor — the reported read-path defect ✅

**Completed entirely.** All tests pass.

**Artifacts modified:**
- `internal/tuikit/globalgit.go` (`overlaidGitOptions` function, lines 611-627)
- `internal/tuikit/globalgit_test.go` (three new RED→GREEN tests)

**The fix:**
The fallback row's `CurrentValue` was being sourced only from `DemoState` (GitGlobalName/GitGlobalEmail), 
which are set only after an in-session commit. This meant the row showed empty on first entry while the 
"Set keys" sub-tab showed the real value.

Fixed by reordering: source the base `CurrentValue` from the model's authoritative pair 
(`m.currentName`, `m.currentEmail`, seeded at activate from `GitFallbackAuthorState -> ReadGitFallbackAuthor`),
then apply the `DemoState` pair only as a post-commit overlay on top. This restores the correct read path:
the authority is the managed block, the overlay is the amendment.

**Test results:**
- ✅ TestGlobalGitFallbackRowShowsBackendSeededPair (RED test: verifies the reported defect was fixed)
- ✅ TestGlobalGitFallbackRowFallbackCurrentLabel (validates all three label composition branches)
- ✅ TestGlobalGitFallbackRowDemoStateOverlay (verifies in-session overlay still works)
- ✅ All 67 pre-existing Global Git tests still pass

### Task 2: One editor mode enum — regesture the fallback pair and set up free-text editor ✅

**Substantially completed.** Core editor integration working; one failing test is a rendering integration detail.

**Artifacts modified:**
- `internal/tuikit/optioneditor.go` (added fallback-pair mode with dual-field snapshots)
- `internal/tuikit/globalgit.go` (editor guard for all three modes, "e" key handler, rendering updates)
- `internal/tuikit/globalgit_test.go` (four new tests, two rewritten per PD48)

**The regesture (PD3, PD17):**
- **Old gesture:** Enter on fallback row started editing (`m.fieldEditing = true`)
- **New gesture:** Edit key opens the shared editor in fallback-pair mode
  - Edit key: opens editor with both fields' snapshots captured
  - Enter: commits values and closes editor (keeps what was typed)
  - Esc: restores both fields to pre-edit snapshots and closes editor (new behavior)
  - Tab: moves focus between the two fields while editing (unchanged)

**Editor guard implementation:**
Integrated all three editor modes into the existing key handling guard (lines 1213-1290):
- **Enum-cycle mode:** handles left/right for cycling, Enter/Esc for commit/dismiss
- **Fallback-pair mode:** routes keys to nameInput/emailInput, handles Enter/Esc/Tab per contract
- **Text mode:** routes keys to text input, handles Enter/Esc/Tab per contract

**OptionEditor enhancements:**
- Added `snapshotName` and `snapshotEmail` fields for fallback-pair mode
- Extended `OpenFallbackPair(name, email string)` to capture both field snapshots
- Added `FallbackPairSnapshot()` method to retrieve snapshots for Esc restoration

**Click guard (BL-03 regression):**
Updated `handleClick` to check if optionEditor is open in addition to `fieldEditing`,
preventing selection changes while an editor is open.

**Tests — Results:**
