## OpenCode Review (opencode-luna)

## 09.6-01

**Summary**
This is a substantial improvement over cycle 1: it establishes shared value metadata, explicit override requests, pure preview paths, and shared overlay builders before screen editors are added. The main remaining risks are incomplete handling of real SSH value domains and silently ignoring overrides for bundle rows.

**Strengths**
- Correctly moves preview/commit convergence into shared builders, addressing the duplicated overlay logic in `cmd/gitid/wiring.go:2441-2477` and `cmd/gitid/lifecycle.go:821-850`.
- Preserves the confirmation boundary enforced by `confirmGate` at `cmd/gitid/lifecycle.go:151-169`.
- Explicitly keeps `Selectable()` and classifier enums outside scope, matching `internal/tuikit/views.go:372-377` and `:590-595`.
- Correctly recognizes that raw machine values currently cross the DTO boundary at `cmd/gitid/wiring.go:2046-2059` and `:2290-2306`.

**Concerns**
- **MEDIUM (downgraded from reviewer's HIGH — orchestrator verification):** The reviewer flagged SSH type-aware classification as HIGH, citing that `ForwardAgent` accepts socket paths/environment values and `AddKeysToAgent` accepts time intervals, yet PD6 classifies them as toggle/enum. Verified against `09.6-01-PLAN.md:165-174`: PD6 explicitly documents this tradeoff by name — *"`ForwardAgent` = toggle, DESPITE its man page also accepting a socket path or a `$ENVVAR` name — offering a socket path through an arrow-cycle is nonsense, so gitid classifies it apply-or-not and leaves the exotic forms to PROP-04."* The classification is a deliberate, rationale-backed decision, not an oversight — so it does not stand as a HIGH architectural gap. The residual point is real, though: no plan test pins what happens when a row's *current* value is already one of these exotic forms (e.g. `ForwardAgent=/tmp/agent.sock`) at first render. That is a legitimate, narrower test-coverage gap.
- **MEDIUM (verified, downgraded from reviewer's cross-plan HIGH):** Bundle overrides are specified to be silently ignored by `WriteRequestedValueFor`. Verified at `09.6-01-PLAN.md:470,490`: `"a bundle row ignores the requested value entirely (a preset is applied or not, never...)"` — this is a documented, intentional design choice, not an accident. It is still a legitimate UX-risk suggestion: the plan never states how (or whether) the UI signals to the user that their typed override on a bundle row was dropped rather than applied.
- **MEDIUM:** Policy metadata is duplicated in `internal/dummytui/fixturebackend.go` rather than structurally linked to backend policy. Independent tests can pass while the two literal tables drift.

**Suggestions**
- Add tests for `ForwardAgent=/tmp/agent.sock`, `ForwardAgent=$SSH_AUTH_SOCK`, and `AddKeysToAgent=30m` as *current* (pre-edit) values, to pin the exotic-current-value display/edit-eligibility behavior PD6 defers to PROP-04.
- Make the "override ignored on a bundle row" behavior visible to the user (a rejected/ignored indicator), rather than only ignoring it structurally.
- Add a fixture-policy consistency test using a generated or table-driven expected classification shared through test data, without importing backend packages into production dummy code.

**Risk Assessment: MEDIUM**
The safety architecture is now mostly sound; PD6's SSH classification and the bundle-override behavior are both deliberate, documented decisions rather than gaps, but each would benefit from the added test/UX suggestions above.

## 09.6-04

**Summary**
This plan addresses the reported defect at its traced source and adds the missing free-text and cancel semantics. The validator and single-editor-mode decisions are strong, but the claimed parity with the wizard's helper-row behavior is not currently true in the live source.

**Strengths**

- Correctly preserves the dedicated fallback writer at `cmd/gitid/wiring.go:3142-3195`.
- Correctly identifies the current Enter/Esc defect at `internal/tuikit/globalgit.go:959-980`.
- Uses the existing field renderer rather than inventing a new widget; `formFieldLine` and `helperLine` are at `internal/tuikit/identities.go:456-474`.

**Concerns**
- **HIGH (orchestrator-verified):** The plan claims reuse of the wizard's fixed-width field plus an "always-reserved" helper row (plan text: `09.6-04-PLAN.md:174,206,250-252` — *"rendered through `formFieldLine` with its always-reserved helper row"*, *"its always-reserved helper row in the DETAIL pane"*). Verified against the live source: `formFieldLine` (`internal/tuikit/identities.go:456-466`) only renders the field itself; helper rows are emitted conditionally by each caller based on focus/validation state (confirmed at `internal/tuikit/identities.go:519-569` — e.g. the Port helper only appears `if focus == sshFieldPort && ...`). The wizard has no "always-reserved helper row" primitive today. Plan 09.6-04 does not modify `identities.go` (grep of the plan confirms it only reads lines 456-474, "reused not reimplemented"), and the only place that could add such a primitive — Phase 9.7 — is not yet executed. This is a real, unaddressed gap: the plan's parity claim does not match current source, and nothing in the plan or a Review Dispositions Ledger entry acknowledges or defers it.
- **MEDIUM:** `ValidateDefaultBranch` is described as differentially tested against Git, but the minimum table does not cover Unicode, repeated special components, ref normalization, or all branch-specific rejection cases. A small hand-selected table can still encode an incomplete grammar.
- **MEDIUM:** The fallback pair is represented by one Options row but owns two fields. The plan specifies this conceptually, but should require a stable display contract for partial pairs and external-origin values before Plan 05 extends the DTO.
- **LOW:** The plan says `Tab` is inert for a single text field, but does not clarify whether it should be swallowed or move focus to another screen control. Existing input modes use explicit focus ownership, so this should be intentional.

**Suggestions**
- Either make `formFieldLine`/`helperLine` genuinely always-reserved in this phase (requires touching `identities.go`), or explicitly defer parity to 9.7 in the plan text and stop claiming it is already reused as-is.
- Add table-driven and fuzz/property checks against `git check-ref-format --branch`.
- Define exact rendering for name-only, email-only, both, and external-origin fallback pairs.
- Test Tab behavior through PTY, not only unit tests.

**Risk Assessment: HIGH**
The reported read-path defect is assigned correctly, but the primary UI consistency requirement depends on a helper-row contract that does not exist yet in the current source — confirmed by direct inspection, not merely asserted by the reviewer.
