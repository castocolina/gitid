<objective>
Make cloning a pre-filled entry into the existing create wizard, backed by a domain function that re-derives every identity-scoped field instead of copying it.

Purpose: D-15 is explicit that clone must NOT get its own write pipeline — the create wizard already owns the test gate, the collision block, the combined ceremony, and the rollback, and a second pipeline would have to reimplement all four. The real work is (a) a domain function that knows which fields are copyable and which must be re-derived, and (b) a pre-filled entry mode on the wizard, which D-02's CLI flag pre-fill will need anyway.
Output: A clone derivation function, a wizard pre-fill mode, and the review flag on exactly the two copied fields.
</objective>

Add `internal/identity/clone.go`.

Define `func SuggestCloneName(source string, taken []string) string`. Start from the source name plus the frozen clone suffix; while the candidate is present in `taken`, append the next integer starting at 2. D-17 requires this bump to be silent and to happen BEFORE the prompt is shown, so the function must be callable with no I/O — the caller supplies the taken list. Match case-insensitively, because SSH host patterns are matched case-insensitively.

Define `type CloneNotices struct { CopiedFields []string }` and `func DeriveCloneInput(source Account, cloneName string, reuseSourceKey bool, targets CloneTargets) (CreateInput, CloneNotices, error)`, where `CloneTargets` carries the resolved gitconfig, ssh config, allowed_signers, and fragment-directory paths so the function stays free of platform lookups.

Implement the copy-versus-re-derive split as an explicit, commented two-column decision so a future reader cannot blur it. Copied: `GitName`, `GitEmail`, `Provider`, `Hostname`, `Port`. Re-derived from the new name: `Name`, `Alias` (via `DefaultAlias`), `Matches` (rebuilding each source match with the new name substituted, preserving the source's match KIND so a `hasconfig` source stays `hasconfig`), `FragmentPath`, and the key path. Never copied at all: the allowed_signers line, which the write pipeline rebuilds from the new email and the new public line.

Populate `CloneNotices.CopiedFields` with the two author field identifiers only. D-14 restricts the review flag to `user.name` and `user.email`; every other field is re-derived and must not be flagged.

Validate before returning: the clone name must be non-empty and must differ from the source name, and the derived alias must pass the same host-block validator the create path uses. Return a typed error naming the offending field so the prompt can render it inline.

Add tests for every behavior above, including a source identity whose match kind is `hasconfig` (asserting the kind survives while the value is re-derived) and a source with multiple matches (asserting each is re-derived, none dropped).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| source identity values → new managed blocks | copied text is interpolated into a new Host block, includeIf, and fragment |
| user-typed clone name → alias and file paths | a name becomes a Host pattern, a fragment filename, and a key filename |
| clone specification → the fail-closed store gate | a stale or foreign proof must not unlock a write |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-05-22 | Tampering | clone name interpolated into managed blocks | high | mitigate | The derived alias is validated by the same host-block validator the create path uses; a typed error names the offending field and no write is attempted. |
| T-05-23 | Spoofing | clone silently shadowing an existing hand-written Host pattern | high | mitigate | The taken-name list unions managed identities with every parsed Host pattern, so the suggestion and the validation both see hand-written aliases. |
| T-05-24 | Elevation of Privilege | copied email carrying a comma into allowed_signers | high | mitigate | The signer line is re-derived by the write pipeline through `keygen.AllowedSignersLine`, never copied from the source, so the CR-18 guard applies. |
| T-05-25 | Repudiation | writing a clone whose alias was never resolution-tested | medium | mitigate | D-16 full two-stage gate plus the fingerprint test proving a foreign proof cannot unlock the write. |
</threat_model>
