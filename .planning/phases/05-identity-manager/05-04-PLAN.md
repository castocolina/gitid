<objective>
Complete the delete semantics the frozen two-option ceremony promises: reference-counted provider cleanup, recoverable key removal, shared-key auto-downgrade, and an advisory unmanaged-reference scan — all as pure or fully-injected domain logic.

Purpose: plan 05-01's tracer landed the Git-only half. The everything half is where the irreversible work lives, and where four separate CONTEXT decisions (D-09, D-11, D-12, D-13) all land on the SAME two approved screens. Getting each one wrong has a distinct, real cost: an orphaned insteadOf block silently breaks every https clone for a provider, an over-eager one breaks a surviving sibling identity, an unbacked key deletion is unrecoverable, and a substring-matching scan produces false warnings that train the user to ignore real ones.
Output: A pure `DeletePlan` preview plus the four behaviors behind it, each tested including its opposite-direction failure mode.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| shared provider state → per-identity delete | one identity's delete can break every other identity on the provider |
| shared key file → per-identity delete | one identity's delete can strand a sibling identity |
| unmanaged user text → scan matcher | a loose matcher produces false warnings that erode trust in real ones |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-05-16 | Denial of Service | orphaned provider rewrite after delete | high | mitigate | Ref-count over managed AND hand-written references; tests assert both the removal and the survival directions. |
| T-05-17 | Denial of Service | over-eager provider rewrite removal breaking a sibling | high | mitigate | The hand-written-alias test is the explicit negative control 05-RESEARCH.md Pitfall 4 asks for. |
| T-05-18 | Denial of Service | deleting a key a sibling identity still uses | high | mitigate | D-12 auto-downgrade keyed off the full sibling slice, not a one-label map; a three-identity test pins it. |
| T-05-19 | Repudiation | confirm copy overclaiming irreversibility | medium | mitigate | The plan carries the archive copy path so the ceremony states the key was removed from active use with a copy at a named path (D-11), never a blanket cannot-be-undone claim for the key. |
| T-05-20 | Tampering | substring alias match deleting or warning about the wrong identity | medium | mitigate | Whole-token matching mirroring the superstring-principal guard, with prefix/suffix/dotted negative tests. |
| T-05-21 | Information Disclosure | scan hits echoing secret-bearing lines | low | accept | Sources are the user's own config files being shown back to the user in their own terminal; no transmission, no logging, and private key files are not among the scanned sources. |
</threat_model>
