**First, create the ONE lifecycle chokepoint per verb (review R-11-CLI).** D-02 requires that the CLI and the TUI run the same test → preview → confirmation → backup → write → re-test ceremony. Reusing only the final write transaction does not prove that: two callers could reach the same writer through different ceremonies. So introduce named lifecycle functions in a new section of `cmd/gitid/wiring.go` (or a sibling `cmd/gitid/lifecycle.go`), and make every other caller a thin adapter over them:

```
type lifecyclePolicy struct {
    DryRun  bool
    Confirm func(preview string) (bool, error) // nil means already confirmed
    Stages  func(stage string)                 // test hook; nil in production
}
type lifecycleResult struct { Backups, Restored, Removed, ArchivedKeyPaths []string; ReTest tester.Result }

func (b *realBackend) runRotate(name string, p lifecyclePolicy) (lifecycleResult, error)
func (b *realBackend) runRepair(name string, p lifecyclePolicy) (lifecycleResult, error)
func (b *realBackend) runDelete(name string, scope identity.DeleteScope, p lifecyclePolicy) (lifecycleResult, error)
```

Each function contains ALL SIX stages in order, calling `p.Stages(<name>)` at each boundary so a test can record the sequence. `p.DryRun` stops the function after the plan/preview stage, before any backup or write. `p.Confirm` is consulted between preview and backup; a nil `Confirm` means the caller already obtained confirmation (the TUI ceremony's case). The backup stage is NOT policy-controlled: it always runs, and a comment at the call site states that no policy field can disable it (D-02).

Plan 05-08's CLI handlers call these same three functions; that is what makes the parity claim structural rather than incidental. Add a test now that asserts the recorded stage sequence for each verb equals its literal expected sequence, and a second test asserting the TUI commit seam contributes no stage of its own.

**Then add the two real commit paths**, mirroring `CommitGit` step for step but delegating the ceremony.

Add `func (b *realBackend) CommitRotate(name string) tea.Cmd` and `func (b *realBackend) CommitNewKey(name string) tea.Cmd`. Each returns a closure that: checks the construction error and returns a `KeyCommitMsg` with the display message on failure; takes `txMu`; calls `b.runRotate` / `b.runRepair` with `lifecyclePolicy{Confirm: nil}`; and marshals `lifecycleResult` into `KeyCommitMsg`. All journal handling, file watching, and rollback live inside the lifecycle function, not in the seam.

Inside the lifecycle functions: build a `mutationJournal`; watch the SSH config target, the gitconfig, the fragment, the allowed_signers file, and both key paths; call the domain function; and on error call `journal.restore()` and return the restored list.

**Add created-file recording to the journal (review R-10).** Watched files must be registered before the transaction starts, but archive filenames are timestamp-generated DURING the transaction and are unknowable at watch time — so a rollback that relies only on watched files leaves archive entries behind. Wire the recording at the point of creation: the composition root's `ArchiveKeyPair`/`CopyKeyPairToArchive` seam closures call `recordCreatedFile` for each returned archive path the moment the primitive returns it. Belt and braces: the domain also reports its archive paths (`RotateResult.ArchivedPrivatePath`/`ArchivedPublicPath`, `DeleteResult.ArchivedKeyPaths`), so the lifecycle function additionally records anything the result names before it decides to roll back.

Document the resolution: on rollback, watched files are restored first, then every recorded creation is removed, so a failed rotation leaves the filesystem exactly as it was found — no orphan archive entry hiding inside a doctor-reserved directory where `--fix` will never surface it. Add a failure-injection test asserting the archive directory contains no entry for this identity after a rolled-back rotation.

Reuse `b.deps` for the domain call — the `identity.Deps` fields plan 05-03 added are already wired there. Do not build a second Deps value inside the commit path.

Add wiring tests over a hermetic fake home for every behavior, using the existing `failCommitAt`-style injection extended with the new steps. Include a concurrency test that launches both commits and asserts serialization, mirroring the existing WR-04 coverage.
