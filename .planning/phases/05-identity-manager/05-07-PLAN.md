<objective>
Wire every Phase 5 ceremony to the user's real machine, and make the manager's read surface honest about what it actually knows.

Purpose: plans 05-03 through 05-06 built the domain logic and the render layer; both are still talking to fixtures in the live binary. This plan closes the composition root — the single place backend types meet view types — and, while there, removes the fabricated defaults the detail renderer currently substitutes for missing values. MGR-03's whole point is that a manager which invents a plausible hostname is worse than one that says the value is absent.
Output: A live binary in which every manager action really writes, really rolls back, and really reports what is on disk.
</objective>

    - Rotating an identity in the live backend archives the old key pair, writes a new pair at the canonical paths, appends the signing line, and re-points the four artifacts, all under one transaction.
    - The delivered commit message carries the real backup paths and the real archived key path.
    - A failure injected at any step of the rotate transaction restores every watched file byte-identically and leaves the original key pair back at its canonical paths.
    - Repairing an identity writes a new key pair and re-points the artifacts without archiving, and its commit message carries an empty archived path.
    - Two overlapping commits cannot interleave: the transaction lock serializes them.
    - A backend whose construction failed answers every commit with an error message and performs no write.
  </behavior>
  <action>
Add the two real commit paths to `cmd/gitid/wiring.go`, mirroring `CommitGit` step for step.

Add `func (b *realBackend) CommitRotate(name string) tea.Cmd` and `func (b *realBackend) CommitNewKey(name string) tea.Cmd`. Each returns a closure that: checks the construction error and returns a `KeyCommitMsg` with the display message on failure; takes `txMu`; resolves the account from `b.accounts()` and returns a clear error when the name is unknown; builds a `mutationJournal`; watches the SSH config target, the gitconfig, the fragment, the allowed_signers file, and both key paths; calls the domain function; and on error calls `journal.restore()` and returns a message carrying the restored list.

Extend the journal to cover key files. `watchFile` snapshots content and mode; confirm it restores a file that did not previously exist by removing it, and that it restores modes as well as bytes — the key pair's 0600 must survive a rollback. If the current implementation does not restore modes, add that and pin it with a test.

Handle the archive interaction with rollback explicitly. The archive step MOVES the old pair out of the canonical paths, so a naive restore would recreate the old bytes at the canonical paths while the archive copy also exists. Decide and document the resolution: on rollback, remove the archive copies created by this transaction after restoring the canonical paths, so a failed rotation leaves the filesystem exactly as it was found. Add a failure-injection test asserting the archive directory contains no entry for this identity after a rolled-back rotation.

Reuse `b.deps` for the domain call — the `identity.Deps` fields plan 05-03 added are already wired there. Do not build a second Deps value inside the commit path.

Add wiring tests over a hermetic fake home for every behavior, using the existing `failCommitAt`-style injection extended with the new steps. Include a concurrency test that launches both commits and asserts serialization, mirroring the existing WR-04 coverage.

## Trust Boundaries

| Boundary | Description |
|---|---|
| domain result → the user's real files | every irreversible removal and every key write crosses here |
| in-memory reducer → real backend | reaching it means reporting success with no write |
| parsed configuration → rendered detail | a fabricated value is a false statement about the user's system |
