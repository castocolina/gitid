## Post-merge fix

**Gate failure discovered and fixed after merge (commit ce2f280)**

The orchestrator independently re-ran `make gate-visual-regression` after merging Plan 03's work and found a deterministic failure on the `gss-options-list:gss-options-browse` region, confirming a gap in execution verification (ONESHOT Rule 10).

**Root cause:** Task 1's first-row-focus change now exposes StrictHostKeyChecking's Provenance field in the detail pane by default (since StrictHostKeyChecking is the first row in the policy table). The real side's Provenance legitimately includes the string "not set (OpenSSH default: ask)" when the option is unset in all gitid-managed config files, sourced from line 3079 in `cmd/gitid/wiring.go`'s `globalSSHProvenanceLabel()` function.

The allowlist entry's predicate was `absent:"not set (OpenSSH default: ask)"` — a hardcoded assumption that this string would never appear on the real side. This was based on the old behavior where a hardcoded middle-row default prevented the Provenance field from being visible when StrictHostKeyChecking was unfocused.

**Corrected predicate (both files):**
- **FROM:** `absent:"not set (OpenSSH default: ask)"`
- **TO:** `absent:"fixture value"`

The real divergence discriminator is the absence of the "fixture value" marker on the real side. The fixture always shows `"fixture value — the demo does not probe this machine"` in the Provenance field, while the real side shows actual provenance (three-tier labels including "not set (OpenSSH default: ...)" for baseline cases, machine-specific VersionNote, and OpenSSH availability data). Both the real and fixture Provenance fields are now legitimately populated; the string is shared catalog reference text, not a live-vs-fixture divergence.
