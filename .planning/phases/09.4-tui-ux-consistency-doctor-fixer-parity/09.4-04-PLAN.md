<objective>
Close UXP-04: give Global SSH's local sub-tab strip a visible bordered
treatment distinct from the main tab bar's flat inline-background format, so
a user can see that left/right here switches sub-tabs rather than main tabs.

Purpose: the sub-tab strip currently renders as one unstyled text line whose
active label is marked the same way the main tab bar marks its active tab.
Nothing on screen distinguishes local navigation from global navigation, so
arriving at the second sub-tab reads as a jump the user did not ask for. D-05
resolves this visually rather than with footer copy.
Output: a bordered, accent-colored strip; one source of truth for how many
rows it costs; and the click affordance proven still working.
</objective>

**Collapse the row accounting to one source before changing the height.**
Today the strip's height is stated in FOUR places: the renderer itself, the
Options top-lines helper, the Storage renderer's budget subtraction (as a
bare literal), and the click handler's row assumption. Three of those hold it
as a literal that is silently wrong the moment the render changes. Introduce
one function or constant that states the height, have all four derive from
it, and make Task 1's row-accounting test the guard. Do this refactor as the
FIRST move of this task, while the strip is still one row and the behavior is
provably unchanged, then change the height. Changing the height first and
fixing consumers afterwards is how the desynced-click-math defect class
already documented in this file's own history recurs.

**Update the click hit-test for both dimensions.** The strip currently
occupies a single known row and its label x-ranges are computed from the raw
label lengths with a one-column leading offset. After bordering: the label
row is no longer the first strip row, so the row test becomes a comparison
against the derived height rather than a fixed row; and the x-ranges shift by
the border's left edge plus its padding. Derive both from the same values the
renderer uses. Treat the border rows and the left border column as inert — a
click there must not activate a label.

**Settle the overflow question with a measurement, not an assumption.**
UI-SPEC's UI Considerations carries this as an explicit backstop and names
the fallback: if the full box's added rows do not fit, use the one-row
title-in-border variant via the existing helper the preview blocks already

has generous headroom, but the Storage sub-tab's stacked preview blocks

measured numbers and the variant chosen in the SUMMARY; do not resolve an
overflow by changing the frame dimensions, which this project forbids.

Do not change any keybinding. The D4 contract that local left/right switches
sub-tabs on this screen (and that this screen is therefore excluded from the

copy/footer-text change as the fix.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| mouse click coordinates -> the strip's hit-test -> sub-tab state, or -> an option row's toggle | a row-offset error here routes a click intended for one target to another |
| rendered frame -> the visual-regression gate | the automated surface that detects layout drift `go build` cannot |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

Task 1's row-accounting test and Task 3's PTY case both guard it. The apply ceremony's preview plus typed confirm remains a second backstop, which is why this is medium and not high. |
