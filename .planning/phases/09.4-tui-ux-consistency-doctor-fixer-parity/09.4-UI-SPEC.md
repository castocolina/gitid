## ⚠ Known Divergence #1: the tab-count math is "6 → 5", not the stale "5 → 4" in ROADMAP.md/REQUIREMENTS.md

`ROADMAP.md`'s Phase 9.4 goal line and `REQUIREMENTS.md`'s UXP-05 text both
say "the main menu goes from 5 tabs to 4." That arithmetic was correct when
UXP-05 was drafted (2026-08-30, based on Phase 8's shipped 5-tab shell) but
is now stale: **Phase 9.2 (2026-08-31) already inserted a 6th top-level
tab**, `TabGitIgnore` ("Global Git Ignore"), AFTER Phase 8 closed. The live
code today (`internal/tuikit/frame.go:58-80`) is:

```go
const (
	TabIdentities TabID = iota
	TabGlobalSSH
	TabGlobalGit
	TabHealth
	TabFixer
	TabGitIgnore
)
var tabLabels    = [...]string{"Identities", "Global SSH", "Global Git", "Health", "Fixer", "Global Git Ignore"}
var tabNavLabels = [...]string{"Identities", "SSH", "Git", "Health", "Fixer", "Ignore"}
```

**Resolution (binding, not a planner choice):** the correct math for THIS
phase is **6 tabs → 5 tabs**, not 5 → 4. The merged tab (`TabDoctor`)
occupies `TabHealth`'s old slot (index 3, key `4`); `TabGitIgnore` shifts
down one slot, from index 5 / key `6` to index 4 / key `5`. Concretely:

```go
const (
	TabIdentities TabID = iota
	TabGlobalSSH
	TabGlobalGit
	TabDoctor
	TabGitIgnore
)
var tabLabels    = [...]string{"Identities", "Global SSH", "Global Git", "Doctor", "Global Git Ignore"}
var tabNavLabels = [...]string{"Identities", "SSH", "Git", "Doctor", "Ignore"}
```

This is exactly the audit CONTEXT.md's own Claude's Discretion item asks
for ("how `TabID`/main-menu numbering renumbers … are there hardcoded
references to a 5-tab layout in tests/screenshots beyond what's explicitly
listed") — the planner must additionally audit every `TabGitIgnore`-keyed
reference (its key changes from `6` to `5`), not just the `TabHealth`/
`TabFixer` removal. `REQUIREMENTS.md`'s UXP-05 prose and `ROADMAP.md`'s
Phase 9.4 goal line should be corrected to "6 tabs to 5" in the same
commit that lands the merge, so the requirement text matches the shipped
reality it describes (same discipline as every other scoped-divergence
note this project records, e.g. D9/T-04-HOSTBLOCK).

## ⚠ Known Divergence #2: the D-03 bracket toggle is a SCOPED exception to the project's one locked checkbox-glyph contract

`internal/tuikit/theme.go` documents ONE frozen glyph pair for every
checkbox in the app (the "D3, checkpoint-2 contract" — its own doc
comment: *"the ONE source of the checkbox/radio glyphs every dummytui
render site draws through"*):

```go
const (
	glyphCheckOn  = "☑"
	glyphCheckOff = "☐"
	glyphRadioOn  = "●"
	glyphRadioOff = "○"
)
```

These four constants are used at 30+ call sites across `identities.go`
(create-flow force-overwrite checkboxes, delete-scope radios, upload
checkboxes, etc.), plus the CURRENT Global SSH/Global Git option-row
toggles (`globalssh.go:759-761`, `globalgit.go:939-941`).

`09.4-CONTEXT.md` D-03 (the toggle-prominence fix) deliberately moves
Global SSH's and Global Git's option-row toggle OFF this shared glyph pair
onto a NEW bracket-style pair — `[ ]` unselected / `[✓]` selected — because
`☑`/`☐` were judged too visually faint at typical terminal font sizes
(the user's literal complaint: *"apenas apreciable, no hay manera de darle
mas tamano al radio rune?"*). This is a **deliberate, scoped exception**
to the D3 "one source" contract, not an oversight — do not read it as
license to also change `identities.go`'s existing `☑`/`☐`/`●`/`○` usage,
which is out of this phase's scope (D-02's scope fence) and untouched by
the user's audit.

**Resolution (binding):** add two NEW theme.go constants, explicitly
scoped, sitting alongside the existing four with a doc comment recording
WHY they diverge and WHERE they apply:

```go
// glyphToggleOn/glyphToggleOff are the Phase 9.4 (UXP-03) bracket-style
// toggle for Global SSH/Global Git option rows ONLY — a deliberate,
// documented exception to the glyphCheckOn/glyphCheckOff pair above,
// because the checkbox glyph was judged too faint at typical terminal
// font sizes for this specific always-visible, frequently-scanned list.
// Do not use elsewhere without a similar documented decision.
glyphToggleOn  = "[✓]"
glyphToggleOff = "[ ]"
```

Both new call sites (`globalssh.go:759-761`, `globalgit.go:939-941`)
switch from `glyphCheckOn`/`glyphCheckOff` to `glyphToggleOn`/
`glyphToggleOff`; the click-hit-test needles at `globalssh.go:698`,
`globalgit.go:841` update to match (`hitNeedle(body, x, y, glyphToggleOff)`
etc.) in the SAME commit — a needle/glyph mismatch would silently break
the existing click-to-toggle affordance (D8, checkpoint-2 contract).

## Typography (TUI-adapted: semantic roles, not px sizes / weights)

Unchanged from Phases 3–8 / `02-STYLE-SPEC.md` §1. Phase 9.4 introduces
**zero new roles**, only the two new glyph constants (Known Divergence #2)
rendered through the SAME two existing roles the checkbox glyph already
used (`Healthy`/green when on, `Hint`/faint when off) — see Color below.

| Role | TUI treatment | Usage in Phase 9.4 |
|------|----------------|-------------------|
| Label | `Bold(true)`, `styleBold` | option-row key name, finding title, sub-tab active label |
| Selected | `styleSelected` (bold + reverse) | the currently highlighted option row / finding row's name |
| Hint / Faint | `Faint(true)`, `styleFaint` | option row's `now: X → Y` / reason sub-line, the `·` non-selectable placeholder, the OFF-state `[ ]` toggle |
| Warning | `Foreground(ANSI 3)` yellow, `styleWarning` | `NeedsAction`/`Differs` tone glyph (unchanged), `SeverityWarning` findings |
| Healthy | `Foreground(ANSI 2)` green, `styleHealthy` | `AlreadySet` tone glyph (unchanged); NEW — the ON-state `[✓]` toggle glyph, bold + green per D-03 |
| Error | `Foreground(ANSI 1)` red, `styleError` | `SeverityError`/`SeverityCritical` findings, destructive-confirm text (unchanged) |
| Accent (ANSI 4, blue) | `Theme.Accent`/`FieldBorder` | NEW — the sub-tab strip's border color (UXP-04) |

**Non-negotiable, carried forward unchanged:** every colored state pairs
with a glyph AND a word — never color alone. The new `[✓]`/`[ ]` toggle
keeps this: the bracket shape itself is legible under `NO_COLOR` (unlike a
color-only distinction), and the bold+green/faint pairing is additive.

layer — at most one selected row plus one bordered strip on screen at a
