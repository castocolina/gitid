<objective>
Reverse Phase 8's FIX-02 split: collapse the standalone Health and Fixer tabs
into a single merged **Doctor** tab that lists every finding (Health's
unfiltered data scope) and carries the inline fix ceremony (Fixer's write
machinery, ported unchanged), so the two screens can no longer report
contradicting counts for the same scan.

This plan lands the compile-atomic core only: the `TabID` enum, the App
shell's tab plumbing, the merged screen model, and every call site the Go
compiler forces to move with them. User-visible copy, the visual-regression
registry, and the real-PTY e2e suite are Plan 02's scope.

Purpose: UXP-05's count-parity bug is not a copy bug — it is two
independently-scoped views over one findings source. A single source of truth
for "here are the findings, here is what I can fix" is the only fix that
cannot drift again (D-06).
Output: `internal/tuikit/doctor_screen.go` (the merged `doctorModel`), a
5-value `TabID` enum, and a green `go test -race ./internal/tuikit/...
./cmd/gitid/...` across the whole in-package test suite.
</objective>
