<objective>
Prove the autonomous upload path against a real GitHub account exactly once, under
ONESHOT.md's Phase 9 External Account Policy, and close the phase's requirements
with evidence.

Purpose: every automated test in plans 09-02 through 09-07 runs against offline PATH
shims. That is the right default — but it means nothing in the phase has yet proven
that gitid's argv is accepted by the real `gh` against a real account, that GitHub
really does require the same key registered twice, or that the post-upload inventory
confirmation sees what it expects. ONESHOT.md's policy authorizes exactly this
validation and specifies the protocol; it also states plainly that if authentication
or scope is unavailable, the blocked evidence is recorded and the run stops — a mock
must not be silently substituted for the required real-account validation.

Output: one recorded real-account validation run, a permanently opt-in test that can
be re-run, and a closed requirement set.

**Safety posture, stated once and binding for this plan.** This is the only plan in
Phase 9 that touches a real external account. It is `autonomous: false` and opens
with a blocking human-action checkpoint, because ONESHOT.md rule 9 requires stopping
for a required confirmation before a real external-account mutation, and because the
account being mutated belongs to the developer, not to the tooling.
</objective>

Structure the single test `TestRealAccountGitHubUploadRoundTrip` as:

1. **Pre-flight.** Resolve `gh` on PATH; run `gh auth status --hostname github.com`;
   probe the token's scopes by attempting a scope-revealing read. If `gh` is absent,
   the session is unauthenticated, or either required scope is missing, call
   `t.Skip` with a message naming exactly which precondition failed. Never `t.Fatal`

   evidence, not a red build.
2. **Run ID.** Build a run identifier that is unique per invocation and contains no
   characters needing shell quoting. Derive it from the current time plus a short
   random suffix. Every title this test creates is
   `gitid-e2e:<run-id>:<purpose>` with `<purpose>` being the registration kind.
   Assert the constructed titles carry the exact prefix before any registration.
3. **Disposable key.** Generate a fresh ed25519 pair into `t.TempDir()` using the
   project's own keygen entry point. Assert the private key never leaves that
   directory and that only the public-key path is passed to the uploader. Never read
   from or write to the real `~/.ssh`.
4. **Register.** Perform the two GitHub registrations through the same
   `uploader.UploadKeys` path the product uses, with the run-prefixed titles.
   Assert both succeed. This is the assertion that proves gitid's argv is accepted by
   the real `gh` against a real account, and that GitHub genuinely accepts the same
   public key twice under two different types.
5. **Record IDs.** Immediately read the inventory and resolve BOTH registrations'
   provider resource IDs by exact title match. Store them in a slice and register a
   `t.Cleanup` that runs the deletion even if a later assertion fails. Assert both
   IDs were found; if either is missing, fail loudly AFTER registering whatever
   cleanup is possible.
6. **Verify.** Assert the inventory reports the key present for both registration
   kinds and that `uploader.HasRegistration` returns true for the generated public
   key against each kind — the real-world confirmation of the D-15/D-16 model and of
   the two-registrations shape `recipes/README.md` describes.
7. **Cleanup.** For each recorded ID: re-read the inventory, re-confirm the entry
   with that ID still carries this run's exact title prefix, and only then call
   `uploader.DeleteKey` with that ID. Never select by a broad query, never delete by
   title alone, and never delete an entry whose prefix does not match. Fail loudly if
   a recorded ID's current title no longer carries the prefix (that means something
   changed underneath the run and the correct action is to stop and report, not to
   delete).
8. **Final sweep.** Re-read the inventory once more and assert zero entries carry
   this run's prefix. Fail the test if any remain, naming them so the developer can
   remove them manually.

Never touch GitLab. Never operate on a key whose title does not carry this run's
