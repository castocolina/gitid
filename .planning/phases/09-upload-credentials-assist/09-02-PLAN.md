## Cross-AI review corrections folded into this plan (09-REVIEWS.md)

The cross-AI review of the pre-execution plan set rated this wave HIGH risk and
named THREE corrections that land here. They are not optional refinements; two of
them are the reason the review cycle did not converge.

**(R1) HERMETIC PROVIDER PATH — suite-wide, this wave, blocking.** Both reviewers
independently traced `newRealCreateFlowCmd` (`e2e/create_flow_pty_e2e_test.go:59-64`)
and found it builds the child's PATH as `<fakeSSHDir>:<ambient PATH>` — the ambient
PATH, and therefore any real authenticated `gh`/`glab` on it, stays resolvable. The
same shape recurs at ~15 environment-construction sites across the `e2e` package
(`os.Environ()` carries PATH through unchanged). The moment Task 1 wires the real
`buildUploaderDeps` into the create flow's autonomous upload trigger, pressing Enter
inside a PRE-EXISTING, unmodified test such as `TestCreateFlow_TestStagePass` can
reach a real GitHub account during a routine unattended `make test-e2e` — exactly
the failure mode `.planning/ONESHOT.md`'s Phase 9 External Account Policy confines
to plan 09-08's opt-in run. Adding a fake-`gh` shim to only the NEW tests does not
close it. Task 2 therefore establishes the hermetic boundary ONCE, for the whole
suite, and Task 3 adds the regression test that proves a pre-existing PTY test
cannot reach a real provider CLI.

*Why a deny-shim rather than a wholesale PATH replacement:* the product legitimately
resolves `ssh`, `ssh-keygen`, `ssh-add`, and `git` through PATH (`internal/tester`,
`internal/keygen`, `internal/gitconfig`, `internal/deps`), and `FakeGitShimDir`
delegates to the real `git`. A PATH containing only shim directories would break
those paths for reasons unrelated to Phase 9. Prepending a directory that OWNS the
names `gh` and `glab` makes the real provider CLIs unreachable by `exec.LookPath`
while leaving every other tool resolution untouched — a narrower change with the
same guarantee, plus a log of any attempt.

**(R2) `ProviderForHostname` must match host boundaries, not substrings.** A bare
`strings.Contains(host, "github")` classifies `github.example.com`,
`notgithub.com`, and `github.com.evil.net` as GitHub and would point an autonomous
upload at the wrong provider. **Decision-conflict resolution, recorded here:** D-11's
parenthetical ("lowercase substring match, same convention as
`upload.Instructions`") describes the PROVIDER-KEY convention — `upload.Instructions`
takes a provider token (`"github"`), not a hostname. The HOSTNAME gate is D-13's
job, and D-13 is explicit that v1.0 autonomous upload is "gated to github.com /
gitlab.com hosts only". This plan honours both: `ProviderForHostname` implements
D-13 with exact-or-subdomain matching, and `DetectFor` implements D-11's
never-cross-route rule by switching on the resulting provider key. Nothing is
weakened; the main-domain gate stops being approximated by a substring and starts
being enforced.

**(R3) No provider subprocess may block or hang the UI.** `gh auth status` can be
slow or hung, and the tracer's `UploadEligibility` was specified as a synchronous
call that could run during rendering. Two changes: the real `Deps.RunCmd` closure
bounds EVERY invocation with a timeout, and eligibility is resolved
asynchronously — off the render path, in `Update`, memoized per provider key, and
re-probed only when `ProviderForHostname`'s (pure, subprocess-free) answer actually
changes. `View` performs no subprocess work.

## Trust Boundaries

|----------|-------------|
| gitid → `gh`/`glab` subprocess | gitid-controlled strings (identity name, hostname, key path, machine hostname) cross into an external process's argv. |

| `gh` stdout/stderr → TUI render | External process output is surfaced to the user. |
| composition root → `uploader.Deps` | A nil function field silently changes behavior instead of failing. |
| e2e test process → the developer's real provider account | From this wave onward, every e2e child that runs the product can trigger an autonomous upload; anything it can resolve on PATH it can execute against a real account. |
| hostname string → provider routing | A hostname the user typed decides which remote service receives their public key. |
| provider subprocess → the TUI event loop | A slow or hung external process must not be able to stall rendering or updates. |
