<objective>
Give the upload section its second and third call sites and land the phase's one new
confirmation ceremony.

Three deliverables: (1) the Identity Manager's register-key modal — the manual
re-trigger surface for an identity that was created before `gh`/`glab` was
authenticated, or whose upload failed; (2) the rotate/repair key-ceremony's own
upload beat, reusing the component rather than reimplementing it; (3) D-04's
interactive old-key delete offer, the ONE place in this phase where autonomy is
deliberately absent because the action is remotely destructive.

Purpose: D-03 is explicit that the upload experience is a shared component reused by
rotate/clone/copy contexts, and D-04 is a USER OVERRIDE of the research
recommendation — the user chose an interactive delete offer over leave-and-report.
Both are load-bearing product decisions, not polish.

Output: upload reachable from the Identity Manager, present in both key-ceremony
modes, and the old-key cleanup offered safely.

**Two decisions resolved here with rationale:**

1. **09-RESEARCH.md Open Question 2 — when the delete offer resolves the old key's
   provider ID:** LAZILY, at result-screen time, from a fresh inventory read. An
   eager resolution during `KeyCeremonyPlan` would cache an ID captured before the
   user even confirmed the rotate, and a provider-side change in between would make
   gitid delete by a stale ID. Fresh-at-use is also what D-18's
   everything-transient posture and D-15's own dedupe-uses-fresh-inventory
   precedent already do everywhere else in this phase.
2. **09-RESEARCH.md Pitfall 3 — `actionMenuRows` and `actionMenuLabels()`:** the
   constant is REPLACED by a derivation from `len(actionMenuLabels())`. Adding the
   fifth row while a separate `= 4` constant still governs the layout math is a
   guaranteed desync; keeping two hand-maintained values and remembering to update
   both is the failure mode, not the fix. This is a scoped, reviewed correctness
   change, called out here so it is not mistaken for an accidental side effect.

## Cross-AI review corrections folded into this plan (09-REVIEWS.md)

**(R3, applied here) Both new sync-shaped seams become asynchronous commands.** The
review found `RotateDeleteOffer` specified as a SYNCHRONOUS method that performs a
fresh provider inventory read, and `RegisterKeyPlan` as a synchronous method that
performs a tool-and-auth probe. Either can freeze the Bubble Tea loop on a slow or
hung provider CLI. Plan 09-02 already resolved the same problem for
`Backend.UploadEligibility` by making it a `tea.Cmd`; this plan applies the identical
treatment to both of these, so the codebase ends with ONE rule — no Backend method
performs provider I/O synchronously — rather than one rule and two exceptions. The
timeout plan 09-02 installed on the real `Deps.RunCmd` still applies underneath as
the second layer.

Neither change costs new frozen copy: the register-key pane already renders its
heading first and its body on arrival, and the rotate result screen's pre-offer state
is the EXISTING grace-window hint, which is also the fallback whenever the offer is
unavailable. In both cases the in-flight state is a state the design already has.

**(R12) A failed remote delete must not lose its reviewed target.** The earlier draft
said to render the failure text but did not say what happens to the confirmed
`{ID, title}` pair. If it is discarded, a retry has to re-resolve the target — and
re-resolution after confirmation is exactly what D-04's "delete the confirmed ID,
never re-resolve" rule forbids. Task 3 specifies the retention and the discard
boundary explicitly.

**(R13, LOW) The action-menu label must communicate immediate execution.** Opening
the register-key pane immediately performs a remote registration — that is deliberate
(opening it IS the opt-in, D-02), but the menu label should not read like a
navigation entry. The frozen label already reads as an action; Task 1 additionally
requires the pane's own status line to state that the registration ran on open, so a
user who opened it by mistake understands what happened.
