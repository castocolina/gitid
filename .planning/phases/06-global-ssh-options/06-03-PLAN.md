<objective>
Make the apply path honest: simulate before writing, re-verify after writing, and say so when a fix would do nothing.

Purpose: `06-CONTEXT.md`'s "Specific Ideas" names this as the phase's identity — the project's prove-before-and-after loop applied to global options. An advisory screen that reports a fix as applied when a later directive shadows it is worse than one that never offered the fix, because it converts a real security gap into a false sense of safety. This plan is also where GSSH-01's "advisory + fixable, never blocking" affordance becomes real behavior rather than a rendered promise: an empty opt-in selection, one combined ceremony, an explicit record of what the user declined, and a rollback-capable write.
Output: An apply ceremony that can be trusted — including when the honest answer is that the fix will not take effect.
</objective>

Build D-04's before-and-after loop as a pure, injectable pair.

Create `internal/globalssh/shadow.go` with `type ShadowFinding struct { Key, WantValue, GotValue, ShadowedBy string }` and `type ShadowResult struct { Findings []ShadowFinding; Inconclusive bool; Reason string }`.

`func Simulate(deps Deps, candidate []byte, keys []string) ShadowResult` is the pre-write half:
1. Create a private directory under the OS temp root with mode 0700 and a file inside it with mode 0600 — OpenSSH refuses a group- or world-writable config, so the mode is a functional requirement, not hygiene. Clean both up with a deferred removal that runs on every path including the error paths.
2. Write `candidate` — the EXACT bytes `EnsureGlobals` produced for this apply, not a reconstruction — into that file.
3. Run the resolution probe against it with the isolated-config flag plus the probe host, reusing `deps.RunSSHG` so the timeout, the group-kill and the argument-slice safety all carry over unchanged.
4. For each requested key, compare the resolved value against the policy's recommended value. Unequal means the fix will be shadowed.
5. Only for keys that came back unequal, call `shadowSourceFor` to name the offending line.
6. Any probe error sets `Inconclusive` with the reason and returns zero findings.

`func Verify(deps Deps, keys []string) ShadowResult` is the post-write half: the same comparison, run against the live machine with no isolated-config flag, so it reflects the real resolution order including files gitid does not manage. This is the same probe `Statuses` already uses; share the invocation rather than duplicating it.

`func shadowSourceFor(deps Deps, key string) string` is the static scan. Read the gitid-visible configuration through `deps.ReadConfig`, walk the stanzas with `sshconfig.AllHostStanzas`, and return a short description of the first stanza-plus-directive that sets `key` ahead of gitid's managed block — for example the matching host pattern together with the directive line. Return an empty string when nothing can be named; the warning then reports shadowing without a culprit rather than inventing one. Put the rule in the doc comment: this function has NO say in whether shadowing happened, because a static scan cannot model OpenSSH's first-obtained-value matching across `Include` and `Match` and would produce false negatives — the probe decides, this only labels.

Test with a fake `RunSSHG` keyed on the arguments it receives so the isolated and live invocations can be distinguished: a winning candidate, a shadowed candidate with a nameable source, a shadowed candidate with no nameable source, a probe error, and a probe timeout. Add one test asserting the temp file's mode and its parent directory's mode, and one asserting both are gone after the call returns on both the success and the error path.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| candidate configuration → temp file → `ssh` subprocess | gitid writes a config file that a subprocess then reads and acts on. |
| async commit goroutine → user's `~/.ssh` | The write runs off the update loop, concurrently with other transactions. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
