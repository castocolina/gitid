<objective>
Make the apply path honest: simulate the WHOLE configuration the way `ssh` will read it, re-verify after writing, and say so when a fix would do nothing.

Purpose: `06-CONTEXT.md`'s "Specific Ideas" names this as the phase's identity — the project's prove-before-and-after loop applied to global options. An advisory screen that reports a fix as applied when a later directive shadows it is worse than one that never offered the fix, because it converts a real security gap into a false sense of safety. `06-REVIEWS.md` found that the previous draft would not actually have proved that: simulating only the candidate target file cannot see directives in the main config under the Include layout, which is the DEFAULT layout on a fresh machine — so the phase's defining guarantee would have been vacuous exactly where it matters most. This plan simulates the graph.
Output: An apply ceremony that can be trusted — including when the honest answer is that the fix will not take effect, and when the honest answer is that gitid could not tell.
</objective>

**Then build the simulation.** Create `internal/globalssh/shadow.go` with:

```
type SimulationGraph struct {
    EntryPointPath     string   // the file ssh actually starts from
    EntryPointContent  []byte
    ManagedTargetPath  string   // equal to EntryPointPath under the in-file layout
    CandidateContent   []byte   // exactly what EnsureGlobals produced for this apply
    IncludePaths       []string // every include target the entry point pulls in, resolved
    IncludeContents    [][]byte
}
type ShadowFinding struct { Key, WantValue, GotValue, ShadowedBy, ShadowedByFile string; ShadowedByLine int }
type ShadowResult struct { Findings []ShadowFinding; Inconclusive bool; Reason string }
```

`func Simulate(deps Deps, graph SimulationGraph, keys []string) ShadowResult` is the pre-write half:
1. Create a private mirror root under the OS temp root with mode 0700 — OpenSSH refuses a group- or world-writable config, so the mode is a functional requirement, not hygiene. Clean the whole tree up with a deferred removal that runs on every path including the error paths.
2. Materialise the graph inside the mirror at mode 0600 per file: the entry point, every include target, and the managed target replaced by `CandidateContent`. Preserve the relative structure so the entry point's Include directives can be rewritten to the mirrored paths and nothing resolves outside the mirror. When `ManagedTargetPath` equals `EntryPointPath`, the candidate IS the entry point and there is exactly one file.
3. Rewrite each Include directive in the mirrored entry point to name the mirrored path. An Include gitid could not resolve is rewritten to a path inside the mirror that does not exist, so the simulation degrades to "that file contributes nothing" rather than silently reading the user's real file — an unresolved include must never leak the real machine into the simulation.
4. Run the resolution probe against the mirrored ENTRY POINT with the isolated-config flag plus the probe host, reusing `deps.RunSSHG` so the timeout, the group-kill and the argument-slice safety all carry over unchanged.
5. For each requested key, compare the resolved value against the policy's recommended value. Unequal means the fix will be shadowed.
6. Only for keys that came back unequal, call `shadowSourceFor` to NAME the offending directive.
7. Any probe error sets `Inconclusive` with the reason and returns zero findings.

State the correction in the doc comment, with its reason: running the probe against the candidate file alone cannot observe a directive in the main config, and under the Include layout — which is the DEFAULT on a fresh machine — the main config is exactly where a user's own `Host *` block lives. A simulation that cannot see it would return a clean result for the case the feature exists to catch.

`func Verify(deps Deps, keys []string) ShadowResult` is the post-write half: the same comparison, run against the live machine with NO isolated-config flag, so it reflects the real resolution order including files gitid does not manage. This is the same probe `Statuses` already uses; share the invocation rather than duplicating it.

`func shadowSourceFor(graph SimulationGraph, key string) (text, file string, line int)` is the static scan. It calls `sshconfig.ScanDirectivesMulti` over the graph's sources in resolution order and returns the last hit that precedes gitid's managed block, together with its file and 1-based line. Return empty values when nothing can be named; the warning then reports shadowing without a culprit rather than inventing one. Put the rule in the doc comment: this function has NO say in whether shadowing happened, because a static scan cannot model OpenSSH's first-obtained-value matching across `Include` and `Match` and would produce false negatives — the probe decides, this only labels.

Test with a fake `RunSSHG` keyed on the arguments it receives so the isolated and live invocations can be distinguished. Add a test asserting the mirror's directory and file modes, one asserting the whole mirror is gone after the call returns on both the success and the error path, one asserting the mirrored entry point's Include directives all point inside the mirror, and one asserting the user's real files' bytes are unchanged.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| candidate configuration graph → mirror directory → `ssh` subprocess | gitid writes a whole config tree that a subprocess then reads and acts on. |
| the user's real config files → the mirror | An unresolved Include in the mirrored entry point could reach back into the real machine. |
| async commit goroutine → user's `~/.ssh` | The write runs off the update loop, concurrently with other transactions. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-12 | Information Disclosure | simulation mirror | high | mitigate | The mirror root is 0700 and every file 0600, created under the OS temp root and removed on every return path including errors; acceptance criteria assert both modes and the cleanup. |
| T-06-37 | Information Disclosure | an Include in the mirror reaching the real machine | high | mitigate | Every Include directive in the mirrored entry point is rewritten to a path under the mirror root; an unresolvable include is rewritten to a non-existent mirror path so it contributes nothing. Asserted by a dedicated criterion. |
| T-06-13 | Tampering | concurrent writes to the same config files | high | mitigate | The apply runs inside `runGlobalSSHApply`, which holds the existing `txMu` — the same mutex the create and Git transactions hold — so no two transactions read-modify-write the config concurrently. |
| T-06-14 | Repudiation | a failed write reported as success | critical | mitigate | The ceremony is async: the receipt is reachable only from an explicit success result, and a failure renders the concrete error with retry/cancel. The apply action is dispatched only after success, and a PTY case drives the failure path end to end. |
| T-06-15 | Tampering | partial write leaving a broken config | critical | mitigate | The commit opens a `mutationJournal`, watches every file it touches, and restores them on any error; acceptance criteria include a byte-identity assertion after an injected failure at both the unit and the PTY level. |
