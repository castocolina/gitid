<objective>
Build the phase's single highest-risk affordance (08-CONTEXT.md D-09): the
Fixer — and ONLY the Fixer — may rewrite exactly ONE existing directive
outside gitid's managed blocks, on a hand-written line, through the full
ceremony (true diff, typed confirm, timestamped backup, mandatory
verification). This plan builds the DETECTION (a genuinely new Coherence
check — today's `coherence.go` IdentitiesOnly check only covers gitid-managed
Host blocks via `deps.ManagedHosts`, never a hand-written one) and the WRITE
(a genuinely new surgical single-directive rewrite primitive — no existing
function in this codebase rewrites one directive's VALUE in place outside a
managed block) for the flagship walk-through: `IdentitiesOnly no -> yes` on a
hand-written `Host clientb.github.com` block.

Purpose: extend "hand-written config is never corrupted" (this project's
CLAUDE.md invariant) into an enforced, verified property on the ONE write
path allowed to touch hand-written lines (D-10), via a documented, scoped
CLAUDE.md amendment (D-09).
Output: a new Coherence/SSH check; `internal/sshconfig`'s surgical rewrite +
verification-loop primitive; the flagship wired end-to-end through
`realBackend.Persist`, the TUI ceremony, and `gitid fix`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Fixer write path -> hand-written ~/.ssh/config | The ONE place in this codebase a write touches content the user authored outside a gitid-managed block |
| Typed confirm input -> destructive-fix gate | User-typed text gates whether the rewrite proceeds |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-04 | Tampering | `RewriteHostDirective`'s new-value write | high | mitigate | Reject newline/control-byte values before write (CR-18 precedent); validate the hostname/pattern via the existing `ValidateHostBlock` path; scope the rewrite to exactly one located line, never a broader block rewrite |
| T-08-05 | Tampering | A fixer write silently corrupting hand-written config outside the targeted directive | critical | mitigate | D-10's mandatory parse->render->re-parse stability check + auto-restore-from-backup on any mismatch; this is the phase's own governing precedent (the false-positive-loop class) applied to the write side |
| T-08-06 | Denial of Service | D-13/D-14's re-run-after-fix loop | medium | mitigate | `maxPasses` hard backstop ported from the archived `convergeFixes` algorithm; the loop only runs on an explicit user-confirmed fix apply, never unattended |
| T-08-07 | Spoofing | Typed-confirm word compared loosely | medium | mitigate | Exact-string match only (`ceremony.go:152`'s existing `confirmEnabled` — reused unchanged, never a case-insensitive or partial match) |
| T-08-SC | Tampering | npm/pip/cargo installs | n/a | n/a | Not applicable — this plan installs no new package (internal-only, Go stdlib `os/exec` for `ssh -G`) |
</threat_model>
