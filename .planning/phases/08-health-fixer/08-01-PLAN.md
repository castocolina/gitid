**The decision (binding for this plan and every later Phase 8 wave):**
`internal/doctor.Run(deps)` becomes the SOLE findings source feeding
`realBackend.InitialState()`. `identity.BuildInventory`'s `Problem` taxonomy
does not disappear — it becomes an INPUT `doctor.Deps` consumes (via
`Identities`, `ManagedHosts`, `KeyPaths`, etc., populated from the same
`identity.BuildInventory`/`Reconstruct` calls the real backend already makes),
not a second, independently-rendered output. This is exactly what
`internal/identity/state.go`'s own doc comment already anticipates ("Phase 8's
doctor is the second consumer of this table", `state.go:101-104`) and it is the
only reading that avoids the duplicate-row failure mode 08-RESEARCH.md's
Pitfall 3 documents (a missing fragment reported once as `ProblemFragmentMissing`
and once as a `doctor.Finding` from `CheckCoherence`). MGR-07's Identity
Manager per-row health badge, which today reads `state.Findings` filtered by
`IdentityName`, keeps working unchanged — it is now reading the CONVERGED list
instead of the narrower `Problem`-only one.

Purpose: prove the architecture is sound on the agent's best-context tokens,
before D-05's 8 new checks and D-09's fix-in-place primitive are built on top
of it (08-RESEARCH.md's own recommendation). Note for the whole phase: D-08
(known_hosts hashing) stays explicitly BACKLOGGED per 08-CONTEXT.md — it is
a Deferred Idea, not implemented by any plan in this wave set, and must not
be picked up opportunistically by any later wave.
Output: `doctor.Finding.Target`; a real, wired `doctor.Deps`; a converged

## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Real disk config -> doctor.Deps | `~/.ssh/config`/`~/.gitconfig`/fragments are user-writable files read into the check engine; malformed or adversarial content must never crash the process |
| doctor.Run() output -> CLI --json | The `--json` envelope is consumed by scripts; field names/types are a contract, not internal state |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-01 | Information Disclosure | `gitid health --json` | low | accept | Findings are the user's OWN config facts (no secrets, no key material) — same posture as the existing `gitid debug caps` output |
| T-08-02 | Denial of Service | `doctor.Run(deps)` on a pathological/huge config | low | mitigate | Every check function is pure over already-read bytes (no unbounded I/O per finding); reuses the existing `internal/doctor/checks` engine's proven bounds, no new unbounded loop introduced |
| T-08-03 | Tampering | `doctor.Deps` construction reading arbitrary paths | low | accept | Every path (`sshConfigPath`, `gitconfigPath`, fragment paths) is gitid's own already-resolved, trusted set of paths (`realBackend`'s constructor fields), identical trust level to every existing read in `wiring.go` |
</threat_model>
