## Release publishing mechanism & permissions

| Option | Description | Selected |
|--------|-------------|----------|
| gh CLI + built-in GITHUB_TOKEN | `gh release create`, no new CI dependency | |
| Dedicated release GitHub Action | Pinned third-party action (e.g. softprops/action-gh-release) | ✓ |

**User's choice:** Dedicated release GitHub Action.
**Notes:** The user first asked "Why gh CLI?" — Claude explained gh is already a project dependency elsewhere (doctor checks, credential upload) so it adds zero new CI dependencies, and confirmed the trigger is already tag-push-driven regardless of which tool is chosen. After that explanation, the user still chose the dedicated action explicitly.

**Permissions:** Not separately re-asked — carried as D-05 (scoped `contents: write` on the release job only, existing jobs unchanged) since this follows directly from "tag-triggered release job" being new and separate from the existing read-only jobs; no alternative was presented as a distinct question.
