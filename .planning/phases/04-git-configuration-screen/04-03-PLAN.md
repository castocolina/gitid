<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Parsed user config → edit form | Existing files may be malformed or carry hostile text. |
| Confirmed multi-file transaction → filesystem | Partial failure can leave identity/signing data incoherent. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-04-07 | Spoofing | allowed_signers principal | high | mitigate | Derive the replacement line from the exact validated Git email and identity-keyed block; assert byte identity after edit. |
| T-04-08 | Tampering | rollback transaction | high | mitigate | Reverse-order restore/remove operation journal with failure injection at every mutation boundary. |
| T-04-09 | Repudiation | failure receipt | medium | mitigate | Return exact failed target and per-target restoration outcome; never render a success receipt on partial restoration. |
| T-04-10 | Elevation of Privilege | user-edited gitdir path | high | mitigate | Normalize beneath the user's HOME, reject traversal/symlink escape before directory creation, and create only after explicit confirm. |
</threat_model>
