Make the REAL `gitid` binary open the approved app shell and drive the create
flow with real backend state. Four moves:

1. **D-14 archive + LEGACY-TRIAGE DROP** — remove the 0.0.1 POC Cobra command
   surface AND the old pre-redesign `tui/` package (per the orchestrator
   directive "archive the old app": both are superseded and cannot render the
   approved design), AND drop the POC add-repo feature (`internal/repoclone` +
   `cmd/gitid/addrepo*.go` + `tui/addrepo*.go`) and the POC interactive-adopt
   modal (`tui/adopt*.go`) — neither has a v1.0 home. One build-safe unit, one
   commit. `internal/adopter` (the ENGINE) is KEPT. Keep `debug` + Cobra
   `completion`. Git history + `.planning/archive/` preserve everything removed.
2. **D-15 rewire** — bare `gitid` in a TTY launches `tuikit.NewApp(realBackend)`
   rendering the approved chrome, replacing the old `tui.Run()` call site.
3. **Real Backend composition root** — a `wiring.go` that constructs the real
   `tuikit.Backend`, filling every create-flow effect (algorithm catalog,
   provider defaults, preview, alias-collision, key-scan, two-stage test,
   storage auto-detect, confirm-write persist, clipboard) from the already-built
   internal packages, and every `identity.Deps` field non-nil per the project's
   injected-seam wiring rule — including the new `ReadPub` seam from plan 03-01
   (L2 real-constructor half). This is ALSO the single backend↔view boundary:
   `keygen.ReusableKey` and `tester.Result` convert into the tuikit-local view
   DTOs here and nowhere else (Codex HIGH #5). It delivers SSHUI-04 (staged temp
   test), SSHUI-05 (macOS globals), and TEST-03 (store-or-adopt with backup) at
   the backend seam; the render deltas layer on in plans 03-04/03-05.
4. **L4 doctor-reserved registration** — D-06 makes the Include'd layout the
   fresh-machine DEFAULT and D-08 writes the macOS `Host *` block on every
   create, so this phase introduces new managed SSH artifacts. They MUST be
   registered doctor-reserved in the SAME phase or `health --fix` re-enters the
   destructive false-positive loop (the project's recurring L4 failure).

Purpose: turn the shared package into a working real application; give the
create flow a real spine end-to-end for the states already in the approved design.
Output: archived POC/tui + dropped add-repo feature, rewired main, the real
Backend composition root, and the L4 reserved registration for everything this
phase writes.

the artifacts it protects.
