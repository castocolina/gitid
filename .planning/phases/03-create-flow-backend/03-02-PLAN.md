<objective>
Perform the D-17 extraction: split the approved, frozen design out of
`internal/dummytui` into a new shared, backend-free presentation package
`internal/tuikit` that BOTH `cmd/gitid-dummy` (fixtures) and `cmd/gitid`
(real backend, plan 03-03) import through a single injected `Backend` seam —
ONE source of truth for the frozen design. Restore the deleted no-backend
import-graph gate (Phase 2 VERIFICATION W2) against the new three-member
allowlist, and widen the `gate-no-backend-files` allowlist for the new package.

This is the critical path: every later create-flow plan wires the real binary
to this package. The design is FROZEN — this plan moves and re-parameterizes
code; it changes ZERO visual output. Every existing dummytui golden/PTY test
must stay green byte-for-byte.

**Backend-free is absolute (Codex HIGH #5).** The seam cannot name a backend
type, so this plan also DEFINES the tuikit-local view DTOs the whole phase
speaks — `ReusableKeyView` (D-10 picker), `TestOutcome` (three constants) and
`TestResultView` (TEST-01/02). Plans 03-04/03-05 render these DTOs; plan 03-03
converts `keygen.ReusableKey`/`tester.Result` into them inside
`cmd/gitid/wiring.go` and nowhere else. The import-graph gate is the arbiter
and is never widened to accommodate a backend type.

Purpose: give the real binary a way to render the exact approved chrome while
staying provably backend-free on the dummy side.
Output: `internal/tuikit` (moved render stack + `Backend` seam),
`internal/dummytui` shrunk to fixtures + `FixtureBackend`, restored gate.
</objective>
