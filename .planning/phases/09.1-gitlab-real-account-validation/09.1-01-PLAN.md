## Deviations from 09.1-PATTERNS.md recorded up front

**Identifier spelling, not mechanism.** PATTERNS.md says to copy Wave 8's bookkeeping
block "verbatim". Copied literally, `e2e/upload_real_account_e2e_test.go` and the new
file would define the same package-level symbols in the same Go package, so the two
tags could never be enabled together and a future combined-tag vet would break. This
plan therefore requires every top-level identifier in the new file to carry a
`GLab`/`GitLab` marker. The MECHANISM — the outstanding-ID map as single source of
truth, the LIFO `t.Cleanup` registration order, delete-by-recorded-ID after scope
re-confirmation, the read-only final sweep — is reproduced exactly, which is what
CONTEXT.md D-05 makes non-negotiable. Spelling is not part of the safety protocol.

**Scope-check transport.** The planning context suggests `glab api
personal_access_tokens/self --jq .scopes`. This plan ships `glab api
personal_access_tokens/self` and parses the `scopes` field in Go with
`encoding/json` instead. Two reasons: it does not assume `glab api` supports a jq
flag (unverified this session), and it puts the exact-member decision in a pure Go
function that the account-free table test in Task 3 can exercise — mirroring exactly
how Wave 8 split `parseGitHubScopeLine` from `missingRequiredScopes`. This adds
`encoding/json` to the import list PATTERNS.md predicted would be unchanged. Task 2
confirms the endpoint's real shape live before the parser is finalized.
