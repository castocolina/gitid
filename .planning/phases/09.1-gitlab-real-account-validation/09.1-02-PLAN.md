## The UP-04 wording tension, resolved up front

UP-04's text in `.planning/REQUIREMENTS.md` says the protocol must confirm "both the
compiled `register-key` path **and the engine's per-registration-title API** against
the live provider." That phrase was drafted by analogy to Wave 8's actual GitHub
shape, before the phase discussion established that GitLab has no per-registration
distinction to prove: `RegistrationCombined` is its only registration type, and
`glab ssh-key delete <id>` is a single namespace with no registration-type routing.
CONTEXT.md D-02 — the later, more specific, explicitly-locked decision — descopes the
second phase. **D-02 governs.** Task 3 closes UP-04 with an evidence note that states
this in the open, rather than either silently ignoring the phrase or quietly
reworking the requirement's substance. The requirement's own wording is not edited: a
requirement is closed by evidence, not by rewording.
</objective>
