<objective>
Prove the whole Global Git architecture end to end on one real option, before any of the other eleven exist.

Purpose: Phase 7 has an unusual risk profile — the screen, its fixtures and its ceremony copy already exist as approved demo code in `internal/tuikit/globalgit.go`, so it is very easy to produce something that LOOKS finished while every value on it is still a fixture. This plan makes exactly one option (`init.defaultBranch`) real through every layer at once: git's own probes, the classifier, the view seam, the ceremony, and the single journal-backed write authority that lands bytes in the include'd baseline file. Everything the remaining plans add — the other eleven rows, the D9 fallback pair, the scrolling list, the CLI — hangs off the seams this plan pins. Getting the precedence model wrong (appending gitid's block below the user's own settings) would silently override the user's config on every machine, which is exactly why D-01's floor-include architecture is proven here rather than assumed later.
Output: One honest row, one resolved write target, one restorable transaction — and a `global-git` sentinel that adopts the POC-era name already present on real machines instead of orphaning it.
</objective>

The effective-values probe runs `git config --show-origin --show-scope --list -z`. Use `-z`: verified empirically at planning time against git 2.55, the record layout is `<scope>` NUL `<origin>` NUL `<key>` LF `<value>` NUL, so a value containing a tab or a newline (the `lg` alias in the recipe contains neither today, but a user's own value may) parses unambiguously, while the non-`-z` tab-separated form does not. Strip the `file:` prefix from the origin when present; git also emits non-file origins (`command line`, `blob:`, `standard input`) — keep those verbatim and treat them as a scope gitid cannot change. Set the command's working directory to a caller-supplied non-repository directory and state WHY in the doc comment: run from inside a repository, `--list` folds repo-local and worktree values into the same output and gitid would report a repo's setting as the machine's global one (the git-side analog of the Phase 6 D-05 isolated-probe discipline). Also set `GIT_CONFIG_NOSYSTEM` unset deliberately — the system scope is real and must be visible, because a system-set value is exactly the "set at a scope gitid cannot change" provenance class. When a key appears more than once, the LAST record wins, matching git's own resolution.

The in-file probe runs `git config --file <path> --list -z` WITHOUT `--includes`, so it reports only keys physically present in that file. This is the same contract `gitconfig.ScanConflicts` already relies on; reference that function in the doc comment rather than restating the reasoning. A missing file is not an error — it is an empty result, the first-run case.

`classify.go` turns the two probe results plus the policy table into rows. Follow `globalssh/classify.go`'s branch order exactly, and say so in the doc comment: decide by VALUE first, by source second.
