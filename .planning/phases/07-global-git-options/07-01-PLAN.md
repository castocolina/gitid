<objective>
Prove the whole Global Git architecture end to end on one real option, before any of the other eleven exist.

Purpose: Phase 7 has an unusual risk profile — the screen, its fixtures and its ceremony copy already exist as approved demo code in `internal/tuikit/globalgit.go`, so it is very easy to produce something that LOOKS finished while every value on it is still a fixture. Getting the precedence model wrong (appending gitid's block below the user's own settings) would silently override the user's config on every machine, which is exactly why D-01's floor-include architecture is proven here rather than assumed later.
Output: One honest row, one resolved write target, one restorable transaction — and a `global-git` sentinel that adopts the POC-era name already present on real machines instead of orphaning it.

The effective-values probe runs `git config --show-origin --show-scope --list -z`. Use `-z`: verified empirically at planning time against git 2.55, the record layout is `<scope>` NUL `<origin>` NUL `<key>` LF `<value>` NUL, so a value containing a tab or a newline (the `lg` alias in the recipe contains neither today, but a user's own value may) parses unambiguously, while the non-`-z` tab-separated form does not. Set the command's working directory to a caller-supplied non-repository directory and state WHY in the doc comment: run from inside a repository, `--list` folds repo-local and worktree values into the same output and gitid would report a repo's setting as the machine's global one (the git-side analog of the Phase 6 D-05 isolated-probe discipline). The in-file probe runs `git config --file <path> --list -z` WITHOUT `--includes`, so it reports only keys physically present in that file.
