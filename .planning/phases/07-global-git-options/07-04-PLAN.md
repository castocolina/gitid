<objective>
Make the screen actually work at its real size, tell the truth when it cannot read the machine, and prove every state with raw keystrokes against the compiled binary.

Purpose: this is the first master-detail screen in the project that carries more than six rows, and `07-UI-SPEC.md` names the row budget as the phase's single highest-risk visual surface — twelve two-line rows do not fit the fixed frame that six did, and the frame cannot change because the visual-regression gate is pinned to it. The scrolling window is decided, not open, but a decided mechanism is not a working one: a scroll offset that the click handler does not know about silently toggles the wrong row, which is precisely the class of defect this project has already hit twice on mouse-driven field focus. This plan also closes the honesty gap that remains after plan 07-03: a screen full of real values still needs to say something truthful when the probe fails, and the demo banner must come off only once nothing on the screen is demo data any more. The UI-wave gate (DLV-04, DLV-06) is satisfied here.
Output: A screen that fits, scrolls, clicks correctly, fails honestly, and has a PTY frame on disk for every state it can reach.
</objective>
