<objective>
Close Phase 9.5: register every new render state in the visual-regression
inventory, promote the phase's UI evidence through a reproducible command, and
mark PROP-01 through PROP-04 complete against quoted evidence with the full
gate battery green.

Purpose: Plans 09.5-01 through 09.5-04 each proved their own behavior in a real
terminal, but none of them registered the new states in the cross-surface
visual-regression inventory or produced tracked evidence. Without that, the four
new browser and entry-flow surfaces are the only ones in the product with no
standing guard against silent visual drift.

Output: the Phase 9.5 ScreenSpec entries with their capture drivers and honest
allowlist classifications, a phase-parameterised frame promoter, the promoted
frames with generated provenance, and the requirement/roadmap bookkeeping backed
by quoted gate output.
</objective>

<decision_record>
**D-K — `gitid-frame-promote` is parameterised by phase rather than bypassed.**
The tool currently hardcodes Phase 9's destination directory and its frame list.
Phase 9.4's own frames reached the tracked tree without it, which is precisely
how a frame with no machine-checked provenance gets committed — the failure the
tool was written to prevent. Add a phase/frame-list parameterisation, keep the
existing Phase 9 invocation's behavior byte-identical and its tests unmodified,
and use it for this phase. Rejected: hand-copying from `tmp/ui-frames/` (no
provenance, and the tool's fail-closed "write nothing unless every frame is
present" guarantee is lost) and writing a second phase-specific promoter (two
promoters that will drift). Reversibility: reversible.
</decision_record>
