<decision_record>
Decisions CONTEXT.md left to Claude's Discretion, resolved here rather than at
a `checkpoint:decision` (this is an unattended autonomous run — the
orchestrator's instruction is to pick the most defensible option and record
the rationale plus the rejected alternative inline).

**D-A — the SSH read function is an EXPORTED sibling of the existing
`effective(deps)`, not a new `ssh -G` parser.** `internal/globalssh/probe.go`'s
`parseResolvedOptions` already parses `ssh -G` output into a general
`map[string]string`, already encodes the verified "a camelCase line never
matches" OpenSSH property, and `effective(deps)` already runs it against
`ProbeHost` — the wildcard-only sentinel. Rejected: extending
`internal/tester.ResolvedConfig` (CONTEXT.md's original pointer) — that struct
is a FIXED five-field shape built for per-identity resolution and would have to
become a map anyway; and re-deriving the parse in a new file, which would risk
dropping the lowercase-matching property. Reversibility: reversible.

**D-B — the filter input owns the keyboard while focused.** While the filter is
focused, `handleKey` returns `handled: true` for every key except `esc`, and
`view()` reports `capturesKeys: true`. Rationale: `app.go`'s globals bind
`1`..`5` for main-tab switching and `q`/`?` for overlays; without the capture
contract, typing a digit into the filter would silently switch main tabs, and a
header click could leave the screen mid-filter. This is byte-for-byte the same
contract `globalGitModel.fieldEditing` and the `Ctrl+P` palette already use.
Rejected: letting plain keys fall through and reserving only letters — a
partial capture is exactly the class of split-brain keyboard contract this
codebase has already been bitten by. Reversibility: reversible.

**D-C — on filter-text change, the selection resets to the FIRST row of the
newly filtered set.** 09.5-UI-SPEC.md leaves this row `⚠ unresolved` with this
exact planner assumption. Rationale: it mirrors `activate()`'s reset-on-entry
discipline (UXP-01/D-01) already applied on both Global screens, and it makes a
selected-but-invisible row structurally impossible rather than defended against.
Rejected: preserving the selection when it survives the filter — correct in the
common case, but it needs a second "did it survive?" predicate that the click
hit-test and the scroll window would both have to agree with, for no user-visible
gain. Reversibility: reversible.
</decision_record>
