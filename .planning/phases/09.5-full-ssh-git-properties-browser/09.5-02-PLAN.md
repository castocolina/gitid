<objective>
Expand the proven Plan 09.5-01 slice sideways onto the Global Git screen: give
that screen its FIRST sub-tab strip — drawn by the same shared renderer Global
SSH uses — and add a `Set keys` sub-tab listing every git config key actually
set on the machine, with its origin file and scope, as the same flat
type-to-filter list.

Purpose: closes PROP-02, and does it while making the strip a single shared
implementation instead of a second copy. Global SSH only GREW an existing
strip; Global Git has never had one, so this is real new plumbing on that
screen — its keyboard contract, its footer hint, and its row budget all change.

Output: the shared strip renderer in `frame.go`, `globalgit.AllSetKeys`, the
`GitSetKeyView` DTO and `GitPropertiesBrowser` seam with both implementations,
the `Set keys` sub-tab with its filter and origin-carrying detail pane, the
frozen copy in both gates, and real-PTY proof through the compiled binary.
</objective>

<decision_record>
**D-D — the sub-tab strip is EXTRACTED into `internal/tuikit/frame.go` and
shared by both screens, not copy-pasted into `globalgit.go`.** 09.5-UI-SPEC.md
leaves the choice open ("rename to the screen-neutral shape or literally share
the helper — Claude's Discretion at plan time") but forbids the outcome of a
second bordered-strip implementation. `frame.go` already owns every
screen-agnostic chrome primitive this codebase has (`frameBodyRows`,
`masterListWidth`, `joinMasterDetail`, `fitPane`, `hitNeedle`,
`spliceTitleIntoTopBorder`), so it is the established home. Rejected:
duplicating `subTabStrip()` into `globalgit.go` — cheaper this week, and it
guarantees the two screens' strips drift the moment either is restyled, which
is exactly the defect class 09.4/UXP-04 just finished fixing. Reversibility:
reversible.

**D-E — `AllSetKeys` reuses `globalgit.effectiveProbe` verbatim and inherits
its `Deps.NonRepoCwd` contract; it does NOT add `--global` or a second probe.**
`effectiveProbe` already runs `git config --show-origin --show-scope --list -z`
from a deliberately non-repository directory and already returns
`map[string]EffectiveEntry{Value, Scope, Origin}` — exactly PROP-02's data
shape, including the system scope, which is real and must stay visible.
Rejected: a new `git config --global --list` probe — it would DROP the system
scope, which is precisely the "set at a scope gitid cannot change" provenance
class this screen exists to expose; and running the existing probe from any
other working directory would fold a repository's local values into a screen
labelled Global (RESEARCH Pitfall 1). Reversibility: reversible.
</decision_record>
