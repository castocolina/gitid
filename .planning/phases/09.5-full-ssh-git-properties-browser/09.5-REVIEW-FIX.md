## Fixed Issues

### CR-01: A custom Git key value containing `"` or `\` writes an unparseable `~/.gitconfig.d/00-baseline`

**Files modified:** `internal/gitconfig/customkeys.go`, `internal/gitconfig/customkeys_test.go`
**Commit:** `136ca1c`
**Applied fix:** Added `validateSubsection` (rejects `"`, `\`, and any non-printable
rune) and a `subsectionEscaper` (`\`→`\\`, `"`→`\"` — git's ONLY two subsection escapes)
used by `RenderCustomKeysBlock` instead of Go's `%q` quoting (which emits `\xNN`/`\uNNNN`
escapes git reads back literally, corrupting the round-trip). `SplitGitKey` now calls
`validateSubsection`. Added exported `ValidateCustomKeyValue` so the plan stage (WR-07)
can reuse the same guard.

### CR-02: The custom SSH directive NAME is completely unvalidated

**Files modified:** `internal/sshconfig/globals.go`, `internal/sshconfig/globals_test.go`
**Commit:** `4351714`
**Applied fix:** `parseGlobalBody` no longer collapses interior whitespace via
`strings.Join(strings.Fields(...), " ")`; it now does
`strings.TrimLeft(trimmed[len(key):], " \t")`, preserving the directive's real value
byte-for-byte on every parse→render round trip. (The name-validation half of CR-02 —
rejecting empty names and the `Host`/`Match`/`Include`/`IgnoreUnknown` structural
keywords before staging — was already present from round 1's `ValidateDirectiveName`;
this round's CR-02 is specifically the whitespace-preservation defect the reviewer
found as "the unreviewed other half.")

### WR-01: The "un-skippable proof gate" lives only in the TUI state machine, never in the writer

**Files modified:** `cmd/gitid/lifecycle.go`, `cmd/gitid/lifecycle_test.go`, `internal/globalssh/validate.go`, `internal/globalssh/validate_test.go`
**Commit:** `aaf31dd`
**Applied fix:** `customDirectiveVerifyAdvisories` now compares the **resolved** written
value against the **resolved** expected value (`globalssh.ResolveDirectiveValue`), not
the typed value against the resolved one — closing a false-positive-advisory class
where OpenSSH canonicalizes a value (e.g. `yes`/`no` normalization) and the naive
string compare wrongly flagged it as a mismatch.

### WR-02: The proof is staged against a different config than the one that gets written when a legacy `_global` block is present

**Files modified:** `internal/globalssh/validate.go`, `internal/globalssh/validate_test.go`
**Commit:** `97e48d2`
**Applied fix:** `stageDirectiveConfig` now writes the candidate `name value` line
FIRST, with the existing body appended after — matching ssh_config's real first-value-
wins resolution semantics, so the staged probe proves the value that will actually take
effect once written, not a value the existing body's first occurrence would shadow.
**Verification note:** this fix encodes a semantic decision about ssh_config directive
precedence (first-match-wins), verified both by a direct test
(`TestStageDirectiveConfigPlacesCandidateBeforeExistingBodySoItWins`) and by the
documented OpenSSH resolution-order reasoning already present in the file's doc
comments — reviewed as correct, not flagged for further human verification.

### WR-05: `EnsureCustomGitKey` folds case over the whole key including the subsection / Set-keys origin leaks the raw sandbox path

**Files modified:** `cmd/gitid/wiring.go`, `cmd/gitid/wiring_test.go`, `e2e/global_git_pty_e2e_test.go`
**Commits:** `63060f9`, `84c54a5`
**Applied fix:** `AllGitSetKeys`/`AllSSHDirectives` now scrub `Value`/`Origin` through
`b.displayMessage`/`b.displayPath` before handing them to the TUI — the same seam
`displayPath` already uses elsewhere to turn a raw absolute sandbox/HOME path into a
`~`-relative one — so a resolved key's origin file path is never leaked verbatim.
Verified at the source level (`funcDisplayScrubCalls` AST helper — real subprocess-
based leak testing was found unreliable on this machine, see Verification Method

**Follow-up (`84c54a5`):** the full `make test-e2e` battery run (see below) surfaced

`~/.gitconfig` display path instead, matching the same convention this same test file
already uses for `~/.gitconfig.d/00-baseline` (`baselineDisplay`, line 711).

### WR-06: A custom Git value containing `#` or `;` is silently truncated by git while the receipt claims the whole value was written

**Files modified:** `cmd/gitid/lifecycle.go`, `cmd/gitid/wiring.go`, `internal/gitconfig/customkeys.go`, `internal/gitconfig/customkeys_test.go`, `internal/tuikit/globalgit.go`, `internal/tuikit/views.go`

### WR-07: A post-write verification failure on the SSH path never rolls back

**Files modified:** `cmd/gitid/lifecycle.go`, `cmd/gitid/lifecycle_customgitkey_test.go`
**Commit:** `4998848`
**Applied fix:** `runCustomGitKeyWrite`'s plan stage now also calls
`gitconfig.ValidateCustomKeyValue(key, value)` before ever touching the filesystem —
rejecting an unwritable value at plan time, before the ceremony's backup/write/verify
sequence begins, so there is nothing to roll back from a doomed write.
