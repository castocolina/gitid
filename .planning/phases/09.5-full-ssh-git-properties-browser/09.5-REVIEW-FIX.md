## Fixed Issues

### CR-01: A custom Git key value containing `"` or `\` writes an unparseable `~/.gitconfig.d/00-baseline`

**Files modified:** `internal/gitconfig/customkeys.go`, `internal/gitconfig/customkeys_test.go`, `internal/gitconfig/reader.go`, `cmd/gitid/lifecycle.go`, `cmd/gitid/lifecycle_customgitkey_test.go`
**Commit:** `2168fe2`
**Applied fix:** Added `validateCustomValue` (a value-render guard, `forbiddenCustomValueCharRE`
rejecting `"`, `\`, `#`, `;`, and leading/trailing whitespace) and wired it into both
`EnsureCustomGitKey` and `RenderCustomKeysBlock`, replacing the too-permissive `validateValue`
call at each site. Added `gitconfig.ValidateGitConfigSyntax` (runs `git config --file <path>
--list`) and made `runCustomGitKeyWrite`'s verify stage load-bearing: on a post-write syntax
failure it now calls `journal.restore()` and returns the error instead of reporting success —
this catches not just the value characters the new guard blocks, but ANY pre-existing foreign
corruption in the baseline file the managed-block writer doesn't touch. RED proof: `git config
--file gc1 --list` on `foo"bar`/`C:\path\to` fails with `fatal: bad config line`, exactly as the
review's own real-git evidence showed; `TestEnsureCustomGitKeyRejectsUnparseableGitSyntaxValues`
and `TestRunCustomGitKeyWriteRollsBackWhenVerifyDetectsUnparseableFile` failed before the fix and
pass after.

### CR-02: The custom SSH directive NAME is completely unvalidated

**Files modified:** `internal/globalssh/validate.go`, `internal/globalssh/validate_test.go`, `cmd/gitid/lifecycle.go`, `cmd/gitid/lifecycle_test.go`
**Commit:** `cd831d9`
**Applied fix:** Added `globalssh.ValidateDirectiveName` (rejects empty, whitespace-only,
multi-token, and the structural keywords `Host`/`Match`/`Include`/`IgnoreUnknown`, case-
insensitively) and `ValidateDirectiveValue` (rejects empty/whitespace-only and embedded
newline/CR/NUL). Both are called at the TOP of `ProveCustomDirective`, before any staged file is
written or `ssh -G` is ever invoked — proven by asserting the fake runner records zero calls for
each rejected candidate. Also called from `runCustomSSHDirectiveWrite`'s plan stage as a
defense-in-depth backstop, mirroring `runCustomGitKeyWrite`'s `SplitGitKey` backstop. Did NOT add
a duplicate "inline stage-1 guard" inside `internal/tuikit/globalssh.go` as the review's fix
sketch suggested — that package is under a hard, test-enforced boundary
(`internal/dummytui.TestNoBackendAllowlist`) that forbids `internal/tuikit` from importing
`internal/globalssh`; the engine-level fix already makes the existing stage-1→stage-2 async
dispatch fail closed with zero subprocess spawned, so the substantive goal (no wasted probe,
immediate, correct rejection) is met without violating that architectural boundary.

### WR-15: The visual-regression gate depends on a real `ssh` subprocess and local OpenSSH behavior

**File:** `internal/screenshot/createflow.go` (`gss-properties-custom-invalid` capture, `step` at ~line 863)
**Reason:** skipped — both remedies the review sketches (route the real-backend capture through an
injected proof seam, or gate the spec's `ApplicableLive` on `exec.LookPath("ssh")` with a
decision-linked non-applicability record) require materially larger, higher-risk changes to a
tightly-coupled, heavily cross-validated spec/capture architecture
(`ValidateScreenSpecs` enforces marker uniqueness and decision-linked non-applicability records
for every surface; `CaptureGlobalSSHScreens` is one shared code path serving both the real and
dummy backends, with no reliable in-function signal for "is this the real backend" to scope a
narrower fix to) than fit safely within this pass's remaining budget. This environment (the one
running the mandatory verification battery below) has `ssh` installed and the gate passes cleanly
here; no currently-observed failure exists. A half-measure that silently swallows a genuine ssh
absence would misrepresent the finding as resolved when it is not, so it is left open rather than
partially patched.
**Original issue:** `CaptureGlobalSSHScreens` forks a real `ssh -G` (bounded by the 3s
`probeTimeout`) synchronously from inside `TestGateVisualRegression` when driving the real backend
through the `gss-properties-custom-invalid` capture. The gate's `StateMarker` for that screen is
the rejection sentence, so the gate fails on any machine where `ssh` is absent, is slow, or
(hypothetically) recognizes the fixed sentinel name `NotARealDirective` — and the failure mode
names a UI regression rather than the actual environmental cause.
