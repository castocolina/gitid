## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Pre-existing latent shell-comment-parsing bug in `FakeSSHDir`'s scan function**
- **Found during:** Task 3, while debugging `TestGlobalSSH_RealPTYCustomDirectiveWrite`'s first failing run.
- **Issue:** The scan function's comment-skip case arm, `#*) continue ;;`, is itself a shell COMMENT at that source position — POSIX `sh` treats an unquoted `#` as opening a comment whenever it begins a new word, including a `case` pattern, so `#*) continue ;;` silently consumed the rest of that source line. The pattern and its `continue` action never existed as parsed code; every scanned comment line fell through to whatever the NEXT arm was. This was latent and harmless before this plan (the fallback had no action), but plan 09.5-04's new unknown-directive `*)` catch-all turned it into a false-positive `Bad configuration option: #` rejection the first time a genuine comment line (`# BEGIN gitid managed: ssh-include`, from gitid's own Include-line managed block) reached the scan with `scan_host=1`.
- **Fix:** Escaped the pattern to `\#*)`, a quoted case-pattern character rather than a comment lead-in. Verified via a standalone throwaway shell script confirming the unescaped form falls through to the default arm and the escaped form matches correctly.
- **Files modified:** `e2e/harness_test.go`
- **Verification:** `TestGlobalSSH_RealPTYCustomDirectiveWrite` failed with the false-positive rejection before the fix and passes after; every pre-existing `FakeSSHDir` test (`TestFakeSSHDirResolvesIdentityFileFromStagedConfig`, `TestFakeSSHDirGlobalSSHProbesReadTheirConfig`) and every pre-existing Global SSH real-PTY test still passes (see Task 3's Acceptance Criteria Evidence below).
- **Committed in:** `e8c35de` (part of Task 3's commit)

**2. [Rule 1 - Bug] `FakeSSHDir`'s known-directive allow-list initially missed `IgnoreUnknown`**
- **Found during:** Task 3, same debugging session.
- **Issue:** `globalssh.renderGlobalBody` unconditionally writes `IgnoreUnknown UseKeychain` at the TOP of every gitid-generated global-ssh block (before the `Host *` line) — a real, always-present OpenSSH directive gitid itself writes, not user input. My first allow-list draft omitted it, so the staged-config proof (which scans the block body starting at `scan_host`'s initial value of 1) spuriously reported it as a `PreexistingError`.
- **Fix:** Added `ignoreunknown` to the fixture's `known_directive()` case, with a comment explaining why it must always be present.
- **Files modified:** `e2e/harness_test.go`
- **Verification:** The ceremony's stage-2 proof beat renders `✓ 'TCPKeepAlive' is a recognized SSH directive.` (not a `PreexistingError` sentence naming `ignoreunknown`) after the fix.
- **Committed in:** `e8c35de` (part of Task 3's commit)

**3. [Rule 3 - Blocking issue] `internal/tuikit/globalgit.go` was missing from the plan's `files_modified` frontmatter**

- **Committed in:** `e8c35de` (part of Task 3's commit)
