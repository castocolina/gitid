## Task 2: Make Doctor Honest About User-Owned Gitignore Block

**What was built:**

1. **Six-branch decision tree for core.excludesfile** (replacing single exact-match predicate):
   - **Branch A:** key unset → WARNING with fix
   - **Branch B2:** key set to different path, file missing → ERROR, no fix (deliberate: won't silently retarget)
   - **Branch B:** key set to different path, file exists → INFO, no fix (user's deliberate choice)
   - **Branch C:** key set to managed target, file missing → ERROR with fix
   - **Branch D:** key set to managed target, file exists, block empty → WARNING with fix
   - **Branch E:** key set to managed target, file exists, block populated → (no error)

2. **Three helper predicates** to replace matchesDefaultGitignorePatterns():
   - `blockIsPopulated(patterns)` — has at least one entry
   - `pointsToManagedTarget(d, configuredPath)` — expands tilde against GitignorePath for comparison
   - `excludesFileExists(d, path)` — checks file existence via d.Stat

3. **Check 4 (curated entries) relaxed** — from WARNING to INFORMATIONAL when block is populated but missing entries. User-edited blocks are treated as configured, not as broken.

4. **Comment headers not penalized** — comparisons use DefaultGitignoreEntries() (comment-free view).

5. **File header doc comment updated** — new six-branch decision table, GIGN-01 citation, user-ownership rationale.

## Task 3: Stop Excludesfile Fix From Reverting User Content or Patching Wrong Block

**What was built:**

1. **Shape-guarding on BOTH files** — before first mutation:
   - `InspectGitignoreFile()` on gitignore target
   - `InspectManagedBlockFile()` on baseline fragment (re-inspected after gitignore write)
   - Both inspections refuse orphan sentinels, duplicate blocks, malformed files

2. **User-content preservation** — managed gitignore block logic:
   - If block is empty/absent: seed with DefaultGitignorePatterns()
   - If block exists and populated: leave byte-identical (user-owned)
   - Comment headers preserved transparently via render→parse round-trip

3. **Block body from inspector, not first-match scan** — ensures read and write paths operate on the same block (cycle-5 HIGH fixed).

4. **Two-way error recovery**:
   - Pre-existing file: restore from filewriter's timestamped backup
   - File created by this fix: remove it so home returns to pre-fix state
   - Both cases avoid half-applied state after second-write failure

5. **Doc comment extended** — explains shape-guarding, user-ownership, write atomicity, and upgrade path (Reset action on screen, not doctor auto-upgrade).

**Tests:**
- ✅ Anti-revert case: edited block preserved byte-for-byte
- ✅ Empty block re-seeded
- ✅ Malformed gitignore file: error before first write
- ✅ Duplicate baseline blocks: error before any write
- ✅ Rollback on second-write failure (pre-existing file case)
- ✅ Rollback on second-write failure (newly-created file case)
