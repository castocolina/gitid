### WR-03 — editor geometry applied only to `view()`'s throwaway copy

**Files modified:** `internal/tuikit/gitignore.go`, `internal/tuikit/app.go`,
`internal/tuikit/gitignore_test.go`
**Commit:** `54e70f3`

**Applied fix:** The review's suggested fix (a `tea.WindowSizeMsg` case
inside `gitIgnoreModel.handleMsg`) assumed `App.Update` forwards
`tea.WindowSizeMsg` to every screen the way it forwards other messages —
verified against the actual source and found FALSE: `App.Update`'s
`case tea.WindowSizeMsg:` short-circuited with `return a, nil` before ever
reaching the `default:` branch's per-screen `handleMsg` dispatch loop, so no
screen could EVER see a resize event through that path. Adapted the fix:
`App.Update` now runs the SAME per-screen forwarding loop for
`tea.WindowSizeMsg` as the `default:` branch (safe for every other screen —
each type-asserts for its own message and no-ops otherwise), and
`gitIgnoreModel.handleMsg` resizes the PERSISTED model on that message. `view()`
still re-applies the same geometry (idempotent) for the per-render height
refinement WR-04 needs (see below) — moving sizing entirely out of `view()`
as the review literally suggested would have reintroduced WR-04's clipping
for any header-content change that isn't a resize (stateErr/applyErr
appearing/disappearing). New test:
`TestGitIgnoreWindowResizePersistsEditorGeometry`.
