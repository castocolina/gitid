# Phase 9.2: Global Git Ignore Management - Context

**Gathered:** 2026-08-30
**Status:** Ready for planning

<domain>
## Phase Boundary

A new top-level TUI screen lets the user review, edit, and confirm the content
of gitid's managed global gitignore block (`~/.gitignore_global`, referenced by
`core.excludesfile`) before it is written. Closes GIGN-01. Today this content is
written non-interactively and unreviewed by `gitid baseline setup` via
`internal/gitconfig.DefaultGitignorePatterns()` / `WriteGlobalGitignore` — this
phase makes that same managed block reviewable, editable, and extendable with
common patterns (venv/env directories, `.env`/`.env.*` with `!.env.example`
negation) the current 13-pattern default set does not cover.

</domain>

<decisions>
## Implementation Decisions

### Catalog scope
- **D-01:** This screen is the reviewable front-end for the SAME managed
  gitignore block `gitid baseline setup` already writes — not a second,
  independent catalog. `internal/gitconfig.DefaultGitignorePatterns()` is
  extended (superset) to include venv/env-directory patterns and the
  `.env`/`.env.*`/`!.env.example` group alongside the existing OS/editor/log
  set. Baseline setup's non-interactive write becomes this screen's
  pre-loaded default content, not a separate write path.
  — **Reversibility:** costly — `WriteGlobalGitignore` and
  `DefaultGitignorePatterns()` are called from both `baseline setup` and
  doctor's `FixExcludesfile`; changing the default pattern set changes what
  every existing caller writes, not just this new screen.

### Interaction model — pre-loaded textarea, not toggle rows
- **D-02:** The screen is a **textarea/text-block editor**, not a per-pattern
  toggle list. It pre-loads with the curated catalog (D-01's extended
  `DefaultGitignorePatterns()`), grouped under comment headers for readability
  (e.g. `# OS / editors`, `# Env files`, `# Temp / build`). The user freely
  edits, adds, or deletes lines — there is no per-row on/off control. A
  **"Reset to defaults"** action restores the original curated content,
  discarding user edits back to the pre-loaded catalog.
- **D-03:** `.env` / `.env.*` / `!.env.example` are seeded together under one
  comment-header group (readability grouping only) — since the interaction
  model is free-text edit, there is no enforced coupling; the user can edit
  any line independently once loaded. This supersedes the earlier
  "toggle-together bundle row" framing discussed before the textarea model was
  proposed — the textarea makes bundling a seeding/grouping concern, not an
  enforcement concern.
- **D-04:** Review/confirm-before-write still applies: the textarea's content
  is the reviewed content — the existing "review before write" step every
  gitid write path uses (CLAUDE.md's confirmation rule) shows the composed
  diff against the current file before calling `WriteGlobalGitignore`, exactly
  as other gitid write paths already do.

### Entry point
- **D-05:** New **top-level main menu item** ("Global Git Ignore" or similar),
  not nested under the existing Global Git Options screen. Gitignore pattern
  management is conceptually distinct from git config key/value options (a
  file-content editor vs. a key/value review table), even though both write
  global, machine-wide state.

### Claude's Discretion
- Exact top-level menu item label and its position/ordering in the main menu.
- Exact category comment-header text and pattern grouping/ordering within the
  pre-loaded textarea seed content (the user confirmed "yes, exactly that" to
  a specific example: `# OS/temp`, `# Env files` — treat that as the shape,
  not the literal final label text).
- Whether "Reset to defaults" is scoped per-session (in-memory, before any
  write) or also offered as a standing re-visitable action after a prior write
  — research/planning should pick the option consistent with how other gitid
  screens with a "reset" affordance behave, if any precedent exists.
- The exact extended pattern list beyond the ones the requirement names
  explicitly (`.venv/`, `venv/`, `.env`, `.env.*`, `!.env.example`) — GIGN-01
  says "similar common directory/extension patterns"; researching common
  language/tool ignore conventions (e.g. `__pycache__/` already present,
  `node_modules/` already present) to round out the catalog is in scope.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `internal/gitconfig.WriteGlobalGitignore` / `RenderGitignoreBlock` /
  `DefaultGitignorePatterns` — the full write/render engine already exists and
  is idempotent + foreign-content-preserving. This phase's job is a TUI
  surface in front of it (extended catalog + editable textarea + review step),
  not new write logic.
- `internal/filewriter.ReplaceBlock` — managed-block composition (sentinel
  `# BEGIN gitid managed: gitignore` / `# END gitid managed: gitignore`,
  confirmed in `e2e/health_fixer_pty_e2e_test.go`).

### Established Patterns
- Every gitid write path shows a diff/preview and requires explicit
  confirmation before calling its `Write*` engine function — this phase's
  textarea-to-write step must follow the same discipline (CLAUDE.md
  Engineering rule; GIGN-01's own text names this explicitly).
- Bundle Tea v2 / Lipgloss v2 / Bubbles v2 stack (per CLAUDE.md's Technology
  Stack) — `bubbles/v2` includes a `textarea` component; check it during
  research/planning as the likely building block for D-02's free-edit surface
  rather than hand-rolling one.

### Integration Points
- Main menu (wherever the existing top-level screen list is wired — likely
  `cmd/gitid/wiring.go` or an equivalent TUI root) gains a new entry per D-05.
- `internal/doctor.FixExcludesfile` and `gitid baseline setup`'s non-interactive
  path continue to call the same `WriteGlobalGitignore`/
  `DefaultGitignorePatterns` engine this phase's screen also drives — D-01
  means the extended pattern set is shared, not duplicated.

</code_context>
