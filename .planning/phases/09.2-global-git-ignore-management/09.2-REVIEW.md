## Summary

Scope: the two commits (`fcd8b36`, `8cce1b5`) that closed `09.2-UI-REVIEW.md`'s three
priority findings on the Global Git Ignore screen — breadcrumb de-duplication, structured
errors + a frozen-copy translation layer, and a glyph on the sentinel-rejection state.

The structured-error redesign in `internal/gitconfig/baseline.go` is mechanically sound
(all five malformed shapes construct a `*ManagedBlockError`, `errors.As` in the translator
is correct, `Error()` back-compat is preserved). But the fix is **incomplete on its own
terms**: the translation is applied at only 3 of 9 sites where a `gitconfig` error can
reach this screen, so the copy-freeze violation the commit claims to close is still
reachable in production — and on the worst path the untranslated message points the user
at the wrong file to hand-repair. That is the single Critical finding.

Beyond that: one logically-unreachable branch survives the error refactor untouched (and
the accompanying test now *documents* the behavior that proves it dead); the
`gignCrumb` anchor change is **not** safe as claimed — the new single "Global Git Ignore"
string appears in the Ctrl+P palette entry and in three `internal/doctor/checks/baseline.go`
`SuggestedFix` strings that the Health/Identities panes render, so the anchor can
false-positive on a non-gign frame and hard-fail `BuildRegionDiffs`; the editor's geometry
is applied only to a throwaway copy so the model that actually handles keystrokes stays at
textarea's 40x6 defaults; and the "frozen" copy introduced here is registered in no
copy-freeze gate and is asserted only against itself.

No security vulnerabilities were found in these files. The sentinel-injection guard in
`NormalizeGitignoreLines` is correct and conservative (it rejects a superset of what
`internal/filewriter` treats as a marker, and it normalizes `\r` **before** splitting, so a
bare-CR smuggled sentinel is caught).

## Critical Issues

### CR-01: `translateGitIgnoreErr` is bypassed on 6 of 9 reachable paths — raw internal diagnostics still reach the screen, and point at the wrong file

**File:** `cmd/gitid/wiring.go:2432-2451` (the translator), leaks at `:2519`, `:2557`, `:2635`, `:2643`, `:2647`, `:2678`

**Issue:**
The translator's own doc comment asserts an invariant the code does not hold:

```go
// translateGitIgnoreErr is the ONLY place a gitconfig error reaches the
// Global Git Ignore screen ...
```

Six reachable call sites return a `gitconfig` error to the UI **without** translating it:

| Site | Path | Error source |
|---|---|---|
| `wiring.go:2519` | `GlobalGitIgnoreState` → `berr` | `inspectBaselineFragment` → `InspectManagedBlockFile(content, "baseline")` |
| `wiring.go:2557` | `GlobalGitIgnoreApplyPlan` → `berr` | same |
| `wiring.go:2635` | `CommitGlobalGitIgnore` | `NormalizeGitignoreLines` (`*SentinelLineError`) |
| `wiring.go:2643` | `CommitGlobalGitIgnore` | `InspectGitignoreFile` (`*ManagedBlockError`) |
| `wiring.go:2647` | `CommitGlobalGitIgnore` | baseline fragment inspect |
| `wiring.go:2678` | `CommitGlobalGitIgnore` (KeyUnset branch) | `InspectManagedBlockFile(..., "baseline")` |

Reachability and impact:

1. **Most damaging (`:2519`).** A user whose `~/.gitconfig.d/00-baseline` carries an orphan
   or duplicated managed block opens the screen. `GlobalGitIgnoreState` returns the raw
   `"line 3: orphan BEGIN sentinel — repair the file by hand before gitid will touch it"`.
   `internal/tuikit/gitignore.go:48-53` assigns it to `stateErr` and `:204` renders it as
   `! line 3: orphan BEGIN sentinel …` — directly under the screen's own
   `~/.gitignore_global` path line. The message names **no file**, so the screen's context
   tells the user to hand-edit `~/.gitignore_global` while the actually-broken file is the
   baseline fragment. For a tool whose contract is "never touch the user's config without
   an accurate, auditable story", misdirecting a manual repair is a correctness defect, not
   a cosmetic one.
2. **`:2643`/`:2647` (commit path).** Reachable as a genuine TOCTOU: the inspect checks run
   *before* the `planToken` comparison at `:2649`, so a file that becomes malformed between
   preview and confirm surfaces the raw diagnostic in the ceremony instead of either the
   frozen malformed copy or `ChangedSincePreview`.

The two new tests only cover the two sites that *were* fixed (`GlobalGitIgnoreState` +
gitignore file, `GlobalGitIgnoreApplyPlan` + sentinel), so nothing fails.

**Fix:** Translate at every boundary, and make the malformed message name its file so the
baseline-fragment case cannot masquerade as a `~/.gitignore_global` problem:

```go
// design.go — parameterize the file instead of hardcoding "~/.gitignore_global"
func GitIgnoreMalformedFileMessage(displayPath string, line int, reason string) string {
	return displayPath + " has a broken gitid marker at line " + strconv.Itoa(line) +
		" (" + reason + ") — repair the file by hand before this screen can read or write it."
}

// wiring.go — one translating wrapper per source file
func (b *realBackend) inspectBaselineFragment() ([]byte, error) {
	path := b.baselineTargetPath()
	content, err := os.ReadFile(path)
	if err != nil && !os.IsNotExist(err) {
		return nil, err
	}
	if _, ierr := gitconfig.InspectManagedBlockFile(content, "baseline"); ierr != nil {
		return content, translateGitIgnoreErr(b.displayPath(path), ierr)
	}
	return content, nil
}
```

and in `CommitGlobalGitIgnore` replace every
`b.displayMessage(<x>err.Error())` for a `gitconfig` error with
`b.displayMessage(translateGitIgnoreErr(<path>, <x>err).Error())`.
Add a test per site (see WR-10).

## Warnings

### WR-01: Logically unreachable branch left in `InspectManagedBlockFile`; the doc comment now contradicts the implementation

**File:** `internal/gitconfig/baseline.go:659-672` (dead branch at `:660-663`), doc at `:608-616`

**Issue:** Inside `if name != openName { … }` the first sub-branch is
`if openName == blockName && name == blockName`. That conjunction implies
`openName == name`, which contradicts the enclosing condition — the branch can never
execute. The refactor converted this dead `fmt.Errorf` into a dead
`newManagedBlockError(..., ManagedBlockReasonMismatchedMarker, ...)` instead of removing it.

The accompanying test change proves it: `internal/gitconfig/baseline_test.go:953-956` now
expects the "mismatched END name" shape to classify as `ManagedBlockReasonUnclosedMarker`
(the END naming a different block is skipped as foreign, the BEGIN is orphaned at
end-of-scan) — i.e. the shape this dead branch was written for never reaches it. Meanwhile
`InspectManagedBlockFile`'s doc comment still advertises five distinct malformed shapes
"returning an error naming the offending line number"; for the mismatched-END shape the
line named is the **BEGIN's** line, not the END's, and the reason is "unclosed marker".

**Fix:** Delete `:660-663`, and correct the doc comment to state the four *classified*
outcomes and that an END naming a different block is treated as foreign (surfacing as
`ManagedBlockReasonUnclosedMarker` at the BEGIN's line):

```go
			if name != openName {
				if openName == blockName {
					continue // foreign END inside our block — leaves ours unclosed
				}
				if name == blockName {
					return ManagedBlockShape{}, newManagedBlockError(lineNo, ManagedBlockReasonMismatchedMarker, ...)
				}
				continue
			}
```

### WR-02: The new `gignCrumb` anchor is NOT unique — the extractor can false-positive on Health/Identities/palette frames

**File:** `internal/screenshot/createflow_regions.go:1358-1388`

**Issue:** The comment justifies safety by reasoning about *tab labels*
(`"internal/tuikit/frame.go's tabLabels has exactly one 'Global Git Ignore' entry"`), but
`gignCrumbIndex` does not compare against the breadcrumb row or match a whole line — it
does `strings.Contains(stripANSI(line), gignCrumb)` over **every line of the frame**. The
string `"Global Git Ignore"` also occurs in rendered output from:

- `internal/tuikit/app.go:131` — the Ctrl+P palette row `"6 · Global Git Ignore"`, rendered
  by `renderPalette()` on *any* tab;
- `internal/doctor/checks/baseline.go:140,151,194` — three `SuggestedFix` strings
  ("…use the Global Git Ignore screen…"), rendered by `internal/tuikit/health_screen.go:206`
  (`"~ Suggested fix: " + sel.SuggestedFix`) and by the Identities detail pane
  (`internal/tuikit/identities.go:2193,4603`).

`BuildRegionDiffs` (`internal/screenshot/createflow_packet.go:1289-1316`) extracts **every**
`AllRegionNames()` region from **every** spec's frames, and a region that differs
live-vs-approved without a declared disposition is a hard error. The `health-findings`
spec (`internal/screenshot/createflow.go:2202-2212`) captures a live doctor run whose
`StateMarker` is literally `"Suggested fix:"`, while the approved side is the dummy's frozen
fixture set — so the moment the seeded fixture home produces any of those three baseline
findings, `gign-body` becomes non-empty and unequal on a Health frame and the gate fails
with `region "gign-body" differs without a screen-specific declared disposition`. The old
doubled string could not collide this way; the fix traded a bug-shaped anchor for a
non-unique one. Latent today (no currently promoted frame contains the string), armed for
the next Health capture.

**Fix:** Anchor structurally rather than by substring — the breadcrumb is always frame row
index 1 (`RenderFrame` emits `header, crumbLine, body…`):

```go
// The breadcrumb is RenderFrame's second row; match it exactly so palette
// rows and doctor SuggestedFix prose can never impersonate this screen.
func gignCrumbIndex(lines []string) int {
	const crumbRow = 1
	if len(lines) > crumbRow && strings.TrimSpace(stripANSI(lines[crumbRow])) == gignCrumb {
		return crumbRow
	}
	return -1
}
```

and add the negative test described in WR-10.

### WR-03: Editor geometry is applied only to `view()`'s throwaway copy — the model that handles keystrokes stays at textarea's 40x6 defaults

**File:** `internal/tuikit/gitignore.go:180`, `:216-217`

**Issue:** `view` has a **value** receiver (`func (m gitIgnoreModel) view(...)`), so
`m.editor.SetWidth(...)` / `m.editor.SetHeight(...)` (both pointer-receiver mutators in
`charm.land/bubbles/v2@v2.1.0/textarea`) mutate a copy that is discarded when `view`
returns. The persistent model — the one `handleKey`/`handleMsg` feed keystrokes to, and the
one `seedEditor` calls `SetValue` on — never leaves `textarea.New()`'s defaults
(`defaultWidth = 40`, `defaultHeight = 6`, textarea.go:30-31).

Consequences: soft-wrap, `MoveToBegin`, up/down-by-visual-line, and viewport scrolling
(`repositionView`) are all computed against a 40-column, 6-row geometry while the frame
renders at roughly 96x20. Any pattern longer than ~40 columns (a long path or `!` negation
pattern is realistic in a gitignore) makes the cursor's model position and its rendered
position disagree, and page-scrolling moves by 6 rows regardless of the visible height.

**Fix:** Size the persistent model on resize, not during render:

```go
func (m gitIgnoreModel) handleMsg(msg tea.Msg, _ DemoState) keyResult {
	if sz, ok := msg.(tea.WindowSizeMsg); ok {
		m.editor.SetWidth(maxInt(20, sz.Width-2))
		m.editor.SetHeight(m.editorRows(sz.Height))
		return keyResult{model: m}
	}
	...
}
```

and leave `view` read-only.

### WR-04: Editor height budget (`bodyBudget-5`) ignores the variable advisory-line count, so the pane is clipped in every state

**File:** `internal/tuikit/gitignore.go:215-217`, `:233-236`

**Issue:** The body writes between 4 and 8 rows before the editor (heading, optional path,
wiring line, optional `stateErr`, optional `applyErr`, optional no-managed-block note,
optional two-target note, blank) — and several of those wrap to two rows at the captured
width. The editor is nevertheless sized to a fixed `bodyBudget-5`, so the composed pane
overflows and `fitPane` truncates it. Every promoted frame shows the symptom, including the
healthy one:
`.planning/phases/09.2-global-git-ignore-management/ui-frames/gign-seeded-defaults.txt`
ends with `… (+3 more lines)`, and `gign-error-malformed-file.txt` with `… (+2 more lines)`.
Combined with WR-03, the bottom rows of the editable area are unreachable visually while
still being reachable by the cursor.

**Fix:** Derive the editor height from the rows actually consumed:

```go
	header := b.String()                     // everything written before the editor
	used := lipgloss.Height(lipgloss.NewStyle().Width(maxInt(20, width-2)).Render(header))
	m.editor.SetHeight(maxInt(1, bodyBudget-used-1))
```

### WR-08: `gitIgnorePreimageToken` concatenates two files with no domain separation

**File:** `cmd/gitid/wiring.go:2399-2402`

**Issue:**

```go
sum := sha256.Sum256(append(append([]byte{}, gitignore...), baseline...))
```

The token is the change-detection guard that stands between a stale preview and a real
write to two of the user's config files. Concatenating the two payloads without a length
prefix or separator makes the hash ambiguous across the boundary: any pair of files whose
concatenation is byte-identical (bytes shifted from the tail of `~/.gitignore_global` to the
head of the baseline fragment) produces the same token, so a genuinely changed pair can pass
the `ChangedSincePreview` check. Low likelihood, but it is a safety check on a write path
and the fix is free.

**Fix:**

```go
func gitIgnorePreimageToken(gitignore, baseline []byte) string {
	h := sha256.New()
	_ = binary.Write(h, binary.BigEndian, uint64(len(gitignore)))
	h.Write(gitignore)
	_ = binary.Write(h, binary.BigEndian, uint64(len(baseline)))
	h.Write(baseline)
	return hex.EncodeToString(h.Sum(nil))
}
```

## Info

### IN-01: `translateGitIgnoreErr` discards the source error instead of wrapping it

**File:** `cmd/gitid/wiring.go:2444`, `:2448`

**Issue:** `errors.New(...)` drops the `*ManagedBlockError` entirely, so `Line`, `Reason`
and the raw diagnostic are unrecoverable downstream. `baseline.go:41-45` advertises that
`Error()` "preserves the original developer-facing diagnostic text for logs and tests" —
after translation nothing can reach it.
**Fix:** Return a small typed error that carries the frozen text as `Error()` and the source
as `Unwrap()`, so `errors.As` still works for logs/tests.

### IN-02: Unknown/zero `ManagedBlockErrorReason` silently reports "unclosed marker"

**File:** `cmd/gitid/wiring.go:2419-2430`

**Issue:** `default:` returns `GitIgnoreMalformedReasonUnclosedMarker`, which is also the
`iota` zero value — a `&ManagedBlockError{Line: 3}` built without a reason, or a future
fourth category, silently mislabels the failure for the user.
**Fix:** Add a neutral phrase (e.g. "a malformed gitid marker") for the default, or make the
zero value an explicit `ManagedBlockReasonUnspecified`.

### IN-03: Standalone END is described to the user as a *mismatched* marker

**File:** `internal/gitconfig/baseline.go:653-656`; copy at `internal/tuikit/design.go:439`

**Issue:** A standalone END has no opening marker at all, but is classified
`ManagedBlockReasonMismatchedMarker`, rendering as "a closing marker that doesn't match its
opening marker".
**Fix:** Either reword the phrase to cover both shapes ("a closing marker with no matching
opening marker") or add a fourth reason.

### IN-04: `parseExcludesfileFromBody` duplicates `parseGitconfigBlockBody`

**File:** `cmd/gitid/wiring.go:2469-2484` vs `internal/gitconfig/baseline.go:203-222`

**Issue:** Two near-identical gitconfig-body scanners (same section/indent/first-`=` rules)
in two packages. A fix to one (quoted values, `#` comments, subsections) will silently miss
the other.
**Fix:** Export the `gitconfig` one (e.g. `gitconfig.ParseBlockKeys`) and delete the copy.

### IN-05: Redundant empty-content guard

**File:** `internal/gitconfig/baseline.go:627-629`

**Issue:** `if len(lines) == 1 && lines[0] == "" && len(content) == 0` — when
`len(content) == 0` the first two conjuncts are always true.
**Fix:** `if len(content) == 0 { return ManagedBlockShape{}, nil }`.

### IN-06: `fmt.Errorf` with no formatting directives

**File:** `cmd/gitid/wiring.go:2561`

**Issue:** `fmt.Errorf("no gitid-managed Git baseline configuration was found — …")` has no
verbs; it is `errors.New` with extra work, and the identical sentence is re-typed at `:2658`
(see WR-06).
**Fix:** Hoist to a package-level sentinel built from the frozen constant.

### IN-07: Dead inner branch in the `ExcludesFile` display path

**File:** `cmd/gitid/wiring.go:2522-2527`

**Issue:**

```go
	view.ExcludesFile = b.displayPath(expandTildeForHome(view.ExcludesFile, b.home))
	if strings.HasPrefix(view.ExcludesFile, b.home) {
		view.ExcludesFile = b.displayPath(view.ExcludesFile)
```

**Fix:** Delete the inner `if`.
