# 09.2-03 SUMMARY — Editable Editor, Visual Registration, and Phase Closure

## Overview

Plan 09.2-03 replaced the read-only Global Git Ignore body with a real, pre-loaded
`textarea.Model` editor (Reset to defaults, edit/reset/apply key map, sentinel refusal, real
paste), registered the screen in the authoritative `RequiredScreenSpecs` visual-regression
inventory, captured the phase's ten PTY evidence frames with provenance, ran the mandatory UI
review, fixed its three confirmed findings, and closes GIGN-01.

## Tasks Completed

### Task 1: Textarea editor, key map, copy-freeze constants
`textarea.Model` replaces the read-only content field. `activate` and the `r` Reset handler
both seed through one helper (`seedEditor`) that pairs `SetValue` with `MoveToBegin()`, pinning
the cursor at row 0 (bubbles' multiline `SetValue` otherwise leaves it on the last inserted
row — the cycle-3 cross-AI HIGH this plan traced into the pinned `charm.land/bubbles/v2@v2.1.0`
source). Key map: `Enter` focuses the editor, `r` resets in memory only, `a` builds the apply
plan from the editor's current value and opens the ceremony; `e` is bound to nothing. Footer,
edit/reset/apply labels, and the discard-unsaved-edits sentence are named constants in
`internal/tuikit/design.go`.

### Task 2: Real-PTY proof of edit, reset, delete-persistence, shortcut-capture, sentinel refusal, bracketed paste
Six new `e2e/gitignore_pty_e2e_test.go` cases drive the compiled binary over a real PTY:
append-and-persist, reset discards the edit, reset-alone writes nothing, a curated default line
deleted by keystroke stays deleted (cursor recipe justified by Task 1's `Line() == 0` contract),
shortcut letters type instead of trigger, a typed sentinel is refused, and a REAL bracketed
terminal paste reaches the editor buffer and lands on disk.

### Task 3: Screen registered in the visual-regression inventory
`gitIgnoreVisualSpecs` + `CaptureGitIgnoreScreens` merged into `ScreenSpecRegistry`
(`internal/screenshot/createflow.go`); `mergeGitIgnoreCaptures` wired into
`cmd/gitid/gate_visual_regression_test.go`. The six registered `ScreenID`s are exactly the six
Approved Base States; the four `gign-error-*` refusal states are tracked evidence only, by
design, and are not expected in the registry.

### Task 4: Evidence capture, UI review, fix pass, and closure

**4a (evidence, committed unconditionally):** the phase's PTY suite ran and its ten frames
(six registered base states + four unregistered error states) were promoted into
`ui-frames/` with `PROVENANCE.md` naming each frame's producing test — committed on its own
(`8cbd0be`, "task 4a").

**4b (the gate):** `/gsd-ui-review 09.2` ran against the compiled binary's real-PTY evidence and
produced `09.2-UI-REVIEW.md` — **14/24**, three confirmed, spec-grounded defects (not taste
calls): the breadcrumb rendered "Global Git Ignore" three times in the top four rows (a direct
spec violation of the Screen Identity table); the malformed-file and sentinel-rejection states
leaked raw `internal/gitconfig/baseline.go` `fmt.Errorf` text instead of the frozen
`09.2-UI-SPEC.md` copy — a violation of this project's own copy-freeze contract; and the
sentinel-rejection state (the screen's one designated Error-red state) rendered with no glyph,
violating the NO_COLOR-legibility "glyph AND word" rule. Per `.planning/ONESHOT.md` Rule 11
these are defects against an already-binding contract, not deferrable "UI review improvements",
so they were fixed in this same plan before closure rather than carried forward.

**Fix pass (this session, before the ledger edits below):**
- `internal/gitconfig/baseline.go` gained two structured error types —
  `ManagedBlockError{Line, Reason}` (from `InspectManagedBlockFile`/`InspectGitignoreFile`) and
  `SentinelLineError{Line}` (from `NormalizeGitignoreLines`) — that preserve the original
  developer-facing diagnostic text in `Error()` for logs and existing tests, but carry the line
  number and a reason category as structured data instead of prose to parse.
- `internal/tuikit/design.go` gained the two frozen `09.2-UI-SPEC.md` message templates
  (`GitIgnoreMalformedFileMessage`, `GitIgnoreSentinelRejectedMessage`, the latter carrying the
  `✗` glyph) and the three reason-phrase constants the spec enumerates.
- `cmd/gitid/wiring.go` gained the ONE translation point (`translateGitIgnoreErr`, matching this
  file's own documented contract that it is the sole backend→view conversion site): a
  `gitconfig.ManagedBlockError`/`SentinelLineError` is rewritten into the frozen `design.go` copy
  before it ever reaches `internal/tuikit`, which still imports zero first-party backend
  packages. Two new tests (`TestGlobalGitIgnoreMalformedFileErrorIsTranslated`,
  `TestGlobalGitIgnoreApplyPlanSentinelErrorIsTranslated`) pin the exact translated text and the
  absence of the raw baseline.go sentence.
- `internal/tuikit/gitignore.go`: both `crumbs: []string{GitIgnoreHeading}` sites became

- `internal/screenshot/createflow_regions.go`: the `gign-body`/`gign-ceremony` region extractor's

  `TestGateVisualRegression`'s region extraction; `gignCrumb` was corrected to the single
  `"Global Git Ignore"` (still unique — no other screen's tab label or breadcrumb equals it),
  so the extractor now anchors on the fixed screen instead of the fixed bug.
- All ten tracked frames were re-captured and re-promoted (every frame's top rows changed) and
