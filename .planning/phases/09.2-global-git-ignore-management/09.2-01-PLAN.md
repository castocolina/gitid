<objective>
Land the production-quality tracer for Phase 9.2: one end-to-end path from a new
top-level nav entry all the way to a confirmed, backed-up write of a FUNCTIONAL global
ignore configuration, wired through BOTH binaries.

"Functional" is the word this plan turns from an assumption into a guarantee. Cross-AI
review (09.2-REVIEWS.md, both reviewers, HIGH) established that writing
`~/.gitignore_global` alone can leave `core.excludesfile` unset or pointing elsewhere —
a confirmed write that Git never reads. This plan therefore makes the screen own the
whole pair: it reports the real wiring state, refuses to pretend, and writes both halves
in ONE reviewed transaction when it safely can.

This slice deliberately carries NO editing yet — the body is the current managed-block
content rendered read-only. Editing (the D-02 textarea and its Reset action) expands out
of this proven spine in plan 09.2-03, and the extended curated catalog (D-01) lands in
plan 09.2-02. Every layer this phase will touch is wired and verified here: nav/frame,
screen model, Backend seam, dummy fixture, real composition root, the gitconfig engine,
and a real-PTY end-to-end proof.

Purpose: prove the architecture (a 6th top-level tab that fits the frozen 100x30 frame, a
new planner seam, and the review-before-write ceremony over the existing
`WriteGlobalGitignore` engine) on one path before any of it is built out.
Output: a reachable, writable Global Git Ignore screen in the real binary that cannot
report success for a configuration Git will ignore.
</objective>

**1. gitconfig engine (`internal/gitconfig/baseline.go`).** Add three functions and change
one.

`NormalizeGitignoreLines(content string) ([]string, error)`: split on newlines (tolerating
carriage returns), right-trim each line, drop the trailing run of empty lines, keep interior
blanks and comment lines as they are, and return a non-nil error naming the offending line
number when a trimmed line starts with either managed-block sentinel prefix `filewriter`
owns.

`ComposeGlobalGitignore(existing []byte, patterns []string) []byte`: the single place the
gitignore managed block is composed. Move the composition expression out of
`WriteGlobalGitignore` into this function and have `WriteGlobalGitignore` call it, so the
review preview and the commit can never diverge. Document on both functions that any caller
needing to show a candidate file must call this and nothing else. Addresses review concern:
ApplyPlan-vs-Commit composition integrity (both reviewers, HIGH; chokepoint cited at
`internal/gitconfig/baseline.go:473-490`).

`InspectGitignoreFile(content []byte) (GitignoreFileShape, error)`: scan the file's lines for
the managed BEGIN and END sentinels whose name is the gitignore block, and classify the file
before anything treats it as readable or writable. Return the block's body and a Managed flag
for the healthy cases (no block; exactly one complete block). Return an error naming the line
number for an orphan BEGIN with no matching END, for an END whose name does not match the
open BEGIN, and for a second complete block — telling the user the file must be repaired by
hand before gitid will touch it. Addresses review concern: malformed/duplicate managed blocks
