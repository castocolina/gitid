Turn the proven read-review-write spine into the editor D-02 specifies: a pre-loaded,
freely editable text block with an explicit Reset to defaults, whose current value is what
the review ceremony diffs and what the confirmed write persists.

landed in 09.2-02. It closes the phase and produces its review evidence.

Purpose: give the user real authorship over the managed block, without loosening the
review-before-write discipline.
Output: the finished Global Git Ignore screen plus captured PTY frames for review.
</objective>

<decisions_implemented>
- **D-02** — a pre-loaded textarea/text-block editor, NOT a per-pattern toggle list, with
  an explicit Reset to defaults.
- **D-03** — the env-file group is seeded together under one comment header (already true
  from 09.2-02) and, because the model is free-text, nothing couples those lines after
  seeding: each is independently editable.
- **D-04** — review/confirm before write is preserved unchanged; the ceremony now diffs the
  EDITED content.
- Claude's discretion (Reset scope): Reset is a standing, always-available in-memory action
  — it restores the curated defaults into the editor and never writes by itself. Re-entering
  the screen separately re-reads from disk (established in 09.2-01), so the two affordances
  answer different questions: "what is on my machine" versus "what did gitid recommend".
</decisions_implemented>

Swap `gitIgnoreModel`'s read-only content field for a `textarea.Model` from

Model changes: keep the fetched `GlobalGitIgnoreView` (its `DefaultContent` is what Reset
restores), add the textarea and an `editing` bool. `activate` seeds the textarea with
`view.Content` via `SetValue`, blurs it, and clears `editing` — so entering the screen
always shows what is on the machine right now, and any unsaved edit from a previous visit
is deliberately discarded (state this in the method's doc comment, mirroring
`globalGitModel.activate`'s own reset-on-entry rationale).

Key map, mirroring `globalGitModel`'s `fieldEditing` precedent exactly:
- browse state: `enter` focuses the editor and sets `editing`; `r` resets the editor to
  `view.DefaultContent` in memory only; `a` builds the apply plan from the editor's current
  value and opens the ceremony; every other key is left unhandled so global navigation
  still works.
- editing state: `esc` blurs and clears `editing`; every other key is forwarded to the
  textarea's `Update` and reported as handled, so this screen's single-letter shortcuts can
  never fire while the user is typing them as text.
- ceremony open: unchanged from 09.2-01.

`view`: size the textarea to the body budget the frame grants (derive width and height from
the `width`/`height` arguments the screen receives, the same way the existing screens
compute their own pane budgets) via `SetWidth`/`SetHeight` before rendering, so a long
content list scrolls inside the editor rather than overflowing the frozen frame. Report
`capturesKeys` true while `editing` or while the ceremony owns the pane, false otherwise.
Footer actions: the edit, reset and apply affordances in browse state; the leave-editing
affordance while editing.

Declare the screen's user-facing copy (the heading, the no-managed-block note, the reset
affordance label, and the apply affordance label) as named constants in
`internal/tuikit/design.go` next to the other screens' frozen copy, and reference them from
the render code rather than inlining literals.

Do NOT add per-pattern toggle controls, checkboxes, or a row-selection model — D-02
explicitly chose free-text editing over toggles, and D-03 explicitly removed any enforced

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| terminal keystrokes -> editor buffer | Arbitrary user text enters the write pipeline |
| editor buffer -> confirmed write | What was reviewed must be exactly what is written |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09.2-10 | Tampering | edited content -> write | high | mitigate | The same content string is passed to the apply plan and to the commit, and the PTY suite asserts the confirmed bytes on disk match the edited body — a preview that could diverge from the write would be a lie in the ceremony |
| T-09.2-11 | Tampering | sentinel injection via the editor | high | mitigate | The normalizer added in 09.2-01 rejects lines beginning with a managed-block sentinel; this plan keeps every write on that path and surfaces the rejection as a ceremony error rather than writing |
| T-09.2-12 | Elevation of Privilege | shortcut keys firing while typing | medium | mitigate | Edit mode captures all keys except the leave-edit key, so a character typed as text can never trigger the apply action; asserted both in unit tests and over a real PTY |
| T-09.2-13 | Repudiation | reset silently mutating disk | medium | mitigate | Reset is in-memory only; a dedicated PTY case asserts no file change and no backup after a reset with no apply |
| T-09.2-SC | Tampering | dependencies | low | accept | `charm.land/bubbles/v2/textarea` is a subpackage of the module already pinned in go.mod; the plan asserts `go.mod`/`go.sum` are unchanged, and no package-manager install runs |
</threat_model>
